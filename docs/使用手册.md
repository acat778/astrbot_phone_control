# astrbot_phone_control_mirror 使用手册


> 本文档是插件 README 的完整使用说明（功能、配置、工具、命令、FAQ 与实现细节）；
> README 只保留快速开始与导航。当前版本：`0.2.1`。


把一台安卓模拟器变成 AstrBot 的“手机”：插件通过远程 ADB 控制模拟器（`adb.host` /
`adb.port` 默认留空，未配置时插件处于假开启状态），让主 Agent 以自身人格在**通过类型识别的已安装 App**（抖音 / 哔哩哔哩 /
小黑盒 / 微信 / 小红书 / 知乎……）中自由浏览，采集内容、截图取证、写入浏览日志，
并支持聊天指令与定时自主浏览、持续刷手机、主动评论 / 被动回复 / 发帖。插件不限定 App：
预置画像只是参考，其余 App 用通用文本抽取兜底。

能力边界：**浏览、记忆、学习与 AI 自主互动**。主动评论、被动回复、发帖默认关闭，开启后
由 AI 用低层工具自主完成，插件只做许可、限额、冷却与记账；模拟器上的 App 由用户自行
安装与登录。

Token 记账按 AstrBot `provider_stats` 的实际 usage 对账（`/phone quota` 明细，
`/phone quota audit [小时]` 对照实际用量）；AI 自主任务（刷手机/学习）可通过
`model.provider_id` 单独选择模型供应商，用户对话不受影响。

## Relay App 控制与连接切换

插件「ADB 连接」支持「直连」和「使用 App 控制」。直连保留 ADB 地址、序列号及程序路径；App 模式显示接入端口，默认6190，容器需发布该端口。两种配置分别保留，切换前停止手机任务，保存后重新加载插件。

App 模式在「Relay App」页面获取配对码，填入手机 Relay。手机先完成本机 TCP ADB 授权或 Android11+ 无线调试配对，再主动建立 TLS 控制连接。App 支持基础控制、中文输入、剪贴板、视频帧截图、节点、播放音频和双向文件传输。断线或超时不重放动作，结果不明确时先观察当前界面。

App 画面来源在「ADB 连接」中选择手机端 scrcpy 视频取帧或按需截图。手机视频由 scrcpy 采集并解码，工具收到新 JPEG 帧；插件端 scrcpy 按直连模式的配置启动。App 0.3.x 继续使用按需截图，升级 App 后按所选视频来源工作。

启用流量抓包后可选择 mitmproxy；App 控制模式还提供「App 抓包」。前者通过认证 TLS 子连接把手机回环代理接入插件 mitmproxy，后者在手机解析 HTTP(S) 请求与响应，再上传有界文本记录和媒体地址。App 抓包支持 HTTP/1.1、分块传输和 gzip 文本；其他编码及二进制响应保留流量元信息。Dashboard 显示抓包方式、运行状态、收到的记录、转发中断及队列丢弃；当前会话没有记录时显示等待新请求。

App 抓包私钥保存在手机私有目录，插件可下载公开 CA。系统 CA 方式要求本机 adbd 已有 root 或已授权 su；手动 CA 方式由目标 App 信任下载的证书。HTTPS 解密取决于目标 App 的 CA 信任策略。停用、切换或失联时撤回本实例代理，设备看门狗按租约收尾。

同机无线配对时，将系统无线调试页和 Relay 置于分屏，保持系统配对窗口打开并及时填写配对端口和六位码。配对成功后，连接端口取自系统无线调试首页的「IP 地址和端口」。

点击或长按在当前页面找不到目标，且本次已召回的 App 经验被标记为失配时，模型会收到重新观察与更新经验的提示，主人不接收此类内部维护通知。未关联经验的目标缺失、节点采集失败、设备断连及实际动作失败仍按错误汇报设置处理。

「Relay App」页面可下载 APK；App 手动检查插件提供的更新并校验包名、签名、版本和摘要，由用户确认安装。覆盖安装保留参数及 ADB 身份，安装后重新打开并启动服务。更换手机或卸载重装后，可在任务空闲时重置 App 配对。详细步骤见 [Relay App 说明](../helper/android-relay/README.md)。

## 能力

- **设备状态**：ADB 连接、型号、分辨率、电量、屏幕开关、前台 App。
- **屏幕感知**：uiautomator dump 解析成紧凑 UI 树（文本 / 描述 / 可点击坐标 / 控件 id）。
- **设备动作**：点击、长按、双击、滑动、文本输入（App 模式通过本机控制通道，直连中文使用 ADBKeyboard 或 scrcpy）、按键、打开/停止 App、截图。
- **信息流浏览**：支持通过类型识别的已安装 App（中文名/别名/包名）→ 校验安装 → 打开 → 等待稳定 →
  逐屏采集/去重/截图/翻页；预置画像（抖音/B站/小黑盒）提供更准的抽取规则，其他 App 用通用文本抽取兜底，
  产出中文摘要；单步失败记入异常列表，不中断整体流程。B 站按卡片 `content-desc`
  结构化解析（一屏可采多条视频，播放/弹幕/时长写入 `meta`），缺失时用
  `resource-id` 兜底，其余 App 回退通用文本摘要；跨屏按条目指纹去重。
- **浏览记忆**：每次浏览写入本地 JSONL 日记（`data/plugin_data/astrbot_phone_control_mirror/diary/diary.jsonl`），
  支持最近记录、关键词检索与提示词注入。
- **定时自主浏览**：基于 AstrBot 原生 cron 主动任务（`add_active_job`），按 cron 表达式
  定期唤醒主 Agent 浏览指定 App；cron 管理器不可用时降级为 asyncio 后台任务。
- **Token 额度、预算、频率与记账对账（默认不限制）**：滚动窗口只统计手机相关 run
  （手机工具/play/任务会话），普通聊天不计入手机额度；运行中先按输入与工具步估算，
  Agent run 结束后按 `umo + run 起始时间` 从 AstrBot `provider_stats` 读取该 run 累计
  实际 usage（输入未缓存/输入缓存/输出）并补记差额（`source=agent_usage`，play 任务同步
  补进本轮预算），查不到时保留估算并 warning；插件内部 `llm_generate` 调用（媒体关键帧
  描述、OCR/read_screen、solver 识图）按返回 usage 立即精确记账
  （`source=internal:xxx`）。`quota.enabled` 默认关闭、
  `max_tokens`/`play_task_tokens`/`per_step_tokens` 默认 0=不限制，每日互动次数与冷却
  默认也不限制。每日次数 -1 不限、0 禁止、正数限额，且配置值不再被程序硬编码上限收敛。
- **自主任务模型可选（刷手机/学习）**：`model.provider_id` 在配置页从已配置对话
  Provider 下拉选择（`_special: select_provider`，留空=默认会话模型）；只作用于 AI
  静默自主任务（持续刷手机、随机玩手机、`/phone play`、后台任务），用户对话与手动
  命令会话不受影响（投递到用户会话的定时自主浏览沿用该会话默认模型）；建议选支持图片输入与工具调用（function calling）的模型，
  Provider 被删除或不存在时任务回退默认模型并记 warning。
- **App 使用经验（记忆）**：AI 用 `phone_app_memory` 查记住的 App 布局/入口/操作步骤，
  按经验操作；成功后用 `phone_app_remember` 记录或更新经验。App 改版导致界面与经验不符
  时重新探索并覆盖更新。`prompt.app_memory_enabled` 控制记录、查询与注入；经验只保存
  插件本地档案（`app_memory.json`），没有存储位置选择。需要按当前 App/页面语义召回时，
  在 `model.app_memory_embedding_provider_id` 选择 Embedding Provider（留空继承聊天记忆选择，再使用默认模型），
  插件使用独立索引；未配置向量模型时按页面关键词与更新时间查找经验。打开 App/读取
  屏幕后自动按当前 App/页面召回经验；操作失败时旧经验累计失效，连续两次标记「可能已
  失效」并提示重新探索更新。同一 App/页面覆盖更新。
- **用户任务优先调度**：AI 自刷/随机/后台玩手机期间用户提出手机相关任务时，先中止当前
  自刷轮次执行用户任务（自刷工具调用立即让路），用户任务结束后自动恢复持续刷。
- **统一设备执行入口与占用**：命令、LLM 工具与定时任务接触设备前都经过同一入口，统一
  校验授权、设备租约、验证暂停、取消代次与剩余期限；同一时刻只有一个任务持有设备
  （用户任务优先，后到的用户任务会收到占用提示），暂停/停止时在途动作批次立即中止；
  任务收尾的 HOME/清后台只在没有其他任务占用设备时执行，避免打断另一个任务。
- **记忆存储可关本地**：`memory.local_enabled` 控制学习档案、浏览日志与聊天记忆是否写入
  插件本地（默认开启）；关闭后不落本地，可依靠 MemoryCompanion
  （`astrbot_plugin_memory_companion`）和/或 LivingMemory
  （`astrbot_plugin_livingmemory`）保存，聊天语义找回同时停用并隐藏；自行刷手机的记忆
  可选用「个人记忆-行动」形式额外记入 MemoryCompanion（默认不计）。
- **插件主人权限**：`security.owner_ids` 非空时只有插件主人可以使用手机工具/命令
  （AstrBot 管理员也不放行），不依赖 AstrBot admins_id。授权校验先于任何调度副作用
  （抢占自主任务、提示词注入、后端预热），非主人请求不会先中止 AI 自主任务再被拒绝。
- **聊天记忆与按喜好分享**：记录最近聊天（全局 3000 条、单会话 100 条），
  `phone_recent_chat` 用于内容看完/玩完后判断会话是否也可能感兴趣，再按喜好把内容
  `phone_share_to_user(target=umo)` 分享到对应群/人（默认静默；分享必须带链接或截图，
  自刷任务须先查聊天记忆；同一目标会话有可配置分享冷却，避免刷屏）。
- **控制/感知后端**：控制优先 scrcpy v5.0.1（低延迟控制注入），不可用时自动回退 ADB；
  minitouch v1.3.2 作为可选 touch 后端（用户自备 binary）。感知帧默认走 ADB 截图
  （`perception.screen_source=adb`），scrcpy 只开控制通道、不做 H264 编码/解码；
  `auto` / `scrcpy` 才启用视频镜像。常驻开关默认开启，关闭时按空闲时限停止，状态里显示当前后端/
  能力/降级原因。
- **任务转后台 + 实时屏幕**：用户委托的多步任务用 `phone_start_background_task`
  转成静默后台任务（session 为空、完成后再主动汇报），避免 QQ 里逐步刷屏；常驻
  `LiveScreenWatcher` 按间隔缓存最近几帧，`phone_live_screen` 回传最新画面、
  `phone_read_screen` 用 OCR/图片理解 Provider 识别验证码/时效文字。
- **评论/回复/发帖（AI 自主操作）**：分主动评论、被动回复与发帖三类，默认关闭；
  主人打开 `security.allow_comments` / `security.allow_passive_replies` /
  `security.allow_posts` 后，AI 先 `phone_interaction_gate` 申请名额（按 kind 使用各自的
  开关、每日上限与冷却；被动回复另有独立每日限额与冷却），再自己用低层工具完成，最后
  `phone_interaction_record` 记录成功/失败。插件只做许可/限额/记账，不编排固定 App 流程。
  **保证程度**：三个开关是 AI 流程约定与插件侧授权/配额/记账，不是底层动作拦截：实际发布
  由 AI 用 `phone_tap`/`phone_input_text` 等低层工具完成，模型若跳过 `phone_interaction_gate`
  申请流程，插件无法从技术上阻止发布；需要硬性保证时不要打开评论/发帖开关。
- **收件箱与被动回复**：`phone_check_inbox` 通用识别大消息 / 回复我的 / 互动消息 / 私信 /
  通知入口，点入后回传 UI 树与可选截图；AI 每次进入 App 先看新消息，读到别人回复后按
  心情与内容判断是否回复（不想回或风险内容直接跳过、不占名额）。
- **持续刷手机与学习**：`auto.mode=自动刷` 且 `auto.activity_enabled=true`（或 `/phone continuous on`）时插件
  自动一轮接一轮地唤醒主 Agent 自由活动（理解刷到的内容，不是空刷），每轮用 `phone_learn`
  记录 1–2 条真正学到的内容（有长期记忆工具也写入），学习档案会注入后续提示词；
  `/phone learn` 查看学习档案（也可在插件面板「学习记录」页查看与检索），`/phone stop`
  立即停止。偏好 App 支持中文名/别名，轮次创建时自动解析成已安装 App（未安装会提示跳过）。
- **人机验证 / 做题**：`phone_solve_verification` 一次调用内部两次视觉模型（第一次识图并
  判断是否人机验证/做题，第二次重新截图给出操作顺序与最终确认点并自动执行），适合滑块、
  顺序点击、识图、拼图与答题/测试页；需要手动精细控制时用 `phone_bypass_verify`
  （capture 截图 / drag 拖拽 / tap_points 顺序点击 / slide 自动滑滑块）。执行后用执行后
  UI 文本做结构化结果判定（已解除 / 答题进度 / 未通过 / 无法确认）；答题按题目进度累计
  （连续答对不会累计成失败次数），
  验证按挑战是否解除判定；单次尝试受 `verification.attempt_timeout_seconds` 约束，超时
  取消在途求解并转人工协助。
- **静默模式与主动分享（兴趣驱动 + 结束后判断）**：普通任务在后台连续操作、不逐条
  汇报；`phone_screenshot` 默认只回传模型不发用户。**行动由 AI 自己的兴趣驱动**：先按
  人格/心情决定是否打开、是否继续，中途不感兴趣直接退出换内容（不为了分享硬看完）；
  看完/玩完后再单独判断是否分享或评论/点赞（分享与互动可以都做、没有先后）。
  分享必须带内容链接或截图（链接优先：App 分享按钮或抓包「可分享链接」；拿不到链接
  自动附当前内容截图），**禁止纯文字分享**；同一目标会话有分享冷却。
- **随机玩手机**：按配置的随机间隔与概率唤醒主 Agent 自由玩手机（默认静默，不把过程
  投递到聊天），看完/玩完后才按兴趣判断是否分享或互动。
- **截图性能与实时页面**：`perception.screenshot_mode`（auto/png/raw）与
  `screenshot_slow_ms` 可调；`phone_screen(mode="image")` 不跑 uiautomator dump，
  只快速截图看画面，适合视频/直播等实时页面。
- **流媒体内容识别**：`phone_watch_media` 录制手机当前正在播放的声音（scrcpy 播放音频
  采集，Android 11+，48kHz 立体声 PCM→WAV）并按间隔抓关键帧，用 AstrBot STT Provider
  转写语音、视觉 Provider 描述画面，返回【媒体识别】录制信息、【语音转写】、
  【画面描述】与降级说明；默认 20s、上限 60s，同一段内容不要反复识别。
  `/phone watch [秒数]` 可直接识别当前在播内容，便于人工验证。
- **分享目标由聊天记忆决定 + 目标会话冷却 + 白天免打扰**：自刷/随机/持续刷玩手机时，
  AI 在内容看完/玩完后用 `phone_recent_chat` 看最近群聊/私聊在聊什么、喜欢什么，再决定
  分享到哪个群或用户；自刷任务未先查聊天记忆时分享工具会拒绝，私聊只分享给最近有交流
  的用户（`auto.share_user_recent_hours`，默认 24 小时）；同一目标会话两次主动分享至少
  间隔 `auto.share_cooldown_minutes`（默认 30 分钟，0=不限），冷却内工具会拒绝，
  避免反复给同一会话发内容刷屏；默认白天 08:00–22:00（中国时区）为分享时段，其余时间
  免打扰、不主动分享（`auto.share_quiet_hours_enabled/share_start_hour/share_end_hour/share_timezone`）。
- **内容新鲜感 / 厌倦感**：插件按标题相似度把刷到的内容归为主题并累计疲劳度；同类内容
  反复出现达到阈值后，提示词会标出「已看腻」主题，要求 AI 降低同类内容的打开/停留
  概率、主动换主题或换 App；一段时间不看按半衰期自然衰减（新鲜感回升）。
  阈值/半衰期/增益/相似度可在配置 `novelty` 卡片调整，**阈值 0 = 关闭该机制**；
  `/phone novelty [status|reset]` 查看或清空状态。
  标题/文本嗅探不额外调用模型：浏览采样、按文本点击、学习记录都会自动记账。
- **截图自动清理**：`perception.screenshot_auto_clean`（默认开）按
  `perception.screenshot_retention_minutes`（默认 3 分钟，可配置）自动删除截图目录中的旧截图：
  插件加载时立即清理一次、之后每 60 秒清理一次，每次截图也会顺带节流清理（30 秒最多一次）；
  只清理 `shots/frames/screenshot/live_frame_last` 前缀的普通文件，不递归、不删用户文件。
- **Dashboard 监控与资料管理**：插件页面 `/#/plugin-view/astrbot_phone_control/dashboard`
  提供监控面板、学习记录与保存的图片三个视图。学习记录支持检索、统计与删除；图片库支持
  查看原图、查看和编辑语义/理由/标签/类型、检索与删除。资料修改即时持久化。
- **配置修改方式**：配置在 AstrBot 原生插件配置页修改（保存后由框架重载插件）；
  `/phone` 命令补丁（如 `/phone continuous on|off`）持久化并立即应用。
- **WireGuard 组网（可选）**：插件内置 userspace WG helper（容器无需 `NET_ADMIN`/`/dev/net/tun`），
  `client` 连接已有 WG 服务器，或 `server` 让装了 WireGuard App 的手机接入；`/phone wg config`
  输出导入用配置，`auto_adb` 可把 ADB 目标切到隧道（ADB over WG），详见「WireGuard 组网」章节。
- **自动清理**：浏览结束时逐包清理后台并保留前台；任务结束时回桌面清理。所有清理入口
  使用 `security.background_keep_packages` 保留名单，默认保留 WireGuard 与 Tailscale；
  桌面、当前输入法与系统入口也会保留。名单可追加其他需要常驻的 App 完整包名。
- **后台清理**：`phone_clean_background` 留空时清理后台，也可指定包名；名单内应用始终保留，
  返回停止数量、保留项、失败原因与内存对比。
- **真机适配**：抖音视频自动播放时 dump 前单击屏幕中心暂停、dump 后单击恢复
  （禁止双击，双击会点赞）；小黑盒冷启动点左上角 X 跳过验证码登录页进游客信息流；
  B 站按结构化 content-desc 一屏多卡解析；dump 失败按 App 画像自动重试并等待。

## 浏览方式：AI 自主浏览为主

插件只提供**工具与参考画像**（启动方式、手势建议、抽取规则等），浏览过程由主 Agent
按自己的人格与兴趣主导：先 `phone_list_apps` 看装了哪些 App（或 `phone_key home` +
`phone_screen` 看桌面图标）决定打开哪个，再 `phone_screen` 观察，自行决定
`phone_swipe` / `phone_tap` / `phone_wait`、何时点开详情或评论、看什么、停留多久；
不熟悉的 App 用低层工具边看边试，不依赖预置画像。`phone_browse` 只是「快速采样
若干条」的便捷工具，不是必经流程。`/phone auto` 创建的主动任务同样是「自由活动」
口吻唤醒 Agent，不要求机械采集固定条数。

## 静默模式与主动分享

默认**静默**：AI 在后台连续操作手机，不逐条汇报；`phone_screenshot` 默认只回传给模型，
只有 `send_to_user=true` 才发到当前聊天。

**行动由 AI 自己的兴趣驱动**：先按人格、心情与好奇心决定要不要点开、要不要继续，
不是因为「会话可能感兴趣」才去刷；中途不感兴趣直接退出换内容，不为了分享硬看完；
看完/玩完后再单独判断「这个内容是否值得某个人看」，想互动就评论/点赞——分享与互动
可以都做、没有先后，不分享也正常。分享工具强制要求内容形态：

- 至少携带**内容链接或截图**，纯文字分享会被自动补齐或拒绝；
- 链接优先：模型显式传入，或由工具自动从最近抓包（`traffic/flows.jsonl`）提取
  `share_url/jump_url/link` 等字段；App 分享按钮会触发分享接口，通常能抓到链接；
- 实在拿不到链接时自动附**当前内容截图**（也可用 `include_screenshot=true` 主动要求）；
- 分享目标必须依据聊天记忆：先 `phone_recent_chat` 看最近群聊/私聊内容，再选具体群/人；
  自刷/随机/持续刷任务未先查聊天记忆会被工具拒绝；私聊只选最近有交流的用户；
- 同一内容只发一次、每轮≤3 条不刷屏；同一目标会话有主动分享冷却
  （`auto.share_cooldown_minutes`，默认 30 分钟，0=不限），冷却内工具拒绝并提示剩余时间；
- 白天时段外默认免打扰。

## 内容新鲜感 / 厌倦感（novelty）

AI 一直刷同类内容会「看腻」：插件把浏览到的标题/文本按词元相似度归为主题，累计疲劳度
（0–100），并在达到阈值后把「已看腻 / 接近阈值」的主题注入本轮请求的临时内容块与自主任务提示词，
要求降低同类内容的打开/停留概率、主动换主题或换 App。一段时间不看，疲劳度按半衰期
指数衰减，新鲜感自然回升。

- 自动曝光记录（不额外调用模型）：`phone_browse` 采样到的每条内容、`phone_tap` 按
  text/desc 点开的内容（权重更高）、`phone_learn` 记录的已理解内容（权重最高）；
- 状态文件：`plugin_data/astrbot_phone_control_mirror/novelty.json`（原子写、损坏容错）；
- 配置卡片 `novelty`（全部实时读取）：
  - `threshold`：厌倦阈值 0–100，默认 60，**0 = 关闭该机制**；
  - `half_life_hours`：疲劳度衰减半衰期（小时），默认 24；
  - `gain`：每次同类曝光的疲劳增量，默认 20；
  - `similarity`：判定同类内容的标题相似度阈值，默认 0.15（中文 2-gram Jaccard，
    纯数字/UI 动作词/通用模板词不参与，且要求至少共享 2 个主题词元，避免只共享一个
    通用词或模板句式就误合并）；
  - `max_entries` / `inject_limit`：主题容量与提示词注入条数；
- `/phone novelty [status|reset]`：查看阈值、Top 疲劳主题，或清空全部状态。

## 随机玩手机

`auto.mode=随机玩` 且 `auto.activity_enabled=true`（默认开）时，插件后台按 `random_interval_min`~`random_interval_max`
分钟随机等待，到点按 `random_probability` 掷骰；命中就以 `run_once` 主动任务唤醒主 Agent
自由玩手机：用 `phone_list_apps`/桌面看图标自己决定玩什么，按人格与当下心情自由探索，
默认不汇报过程，只有有趣内容才分享；任务 `payload.session` 为空（静默，不投递到聊天），
结束前会清理后台。`share_only_interesting` 控制是否只在有趣时才分享。

## Token 额度、预算、频率与记账对账（默认不限制）

**默认全部不限制**：`quota.enabled=false`、`max_tokens=0`、`play_task_tokens=0`、
`per_step_tokens=0`；互动每日上限与冷却默认 0（不限次数/无冷却）；随机间隔/持续刷间隔
只保留下限、不设上限。配置里的数值不再被程序硬编码最大值收敛（如额度可填任意大、
间隔可填任意小/大），主人显式填正数时才生效。`/phone quota` 查看额度与对账明细；
`/phone interactions` 显示「不限次数 / 无冷却」。

用量统计分三层，最终以 AstrBot 的实际 usage 为准：

1. **运行中估算**：`on_llm_request` 对手机相关请求估算输入 tokens（CJK 约 1.5/字符、
   ASCII 约 1/4 字符），每个请求记录一次；`on_using_llm_tool` 每次手机工具调用后按
   `per_step_tokens` 估算下一轮 LLM 开销（默认 0=不估算）。
2. **Agent run 结束对账（实际 usage）**：run 结束后按 `umo + run 起始时间` 从 AstrBot
   `provider_stats` 读取该 run 的累计实际用量（输入未缓存/输入缓存/输出，含工具循环中间
   调用、工具 schema、图片与缓存输入），与本次 run 已记账估算的差额补记到额度
   （`source=agent_usage`，play 任务同步补进本轮预算）；查不到（异步写入未完成/DB 异常/
   第三方 runner）时保留估算并记 warning，不虚构实际值。
3. **插件内部调用精确记账**：插件自己的 `llm_generate` 调用（流媒体关键帧描述、
   `phone_read_screen`、`phone_solve_verification` 识图）按返回的 usage 立即记账
   （`source=internal:media_vision` / `internal:read_screen` / `internal:solve_verification`
   等）；usage 缺失时按提示词文本与图片数保守估算兜底。

记账条目 `token_usage.jsonl` 带 `input_other` / `input_cached` / `output` / `actual`
字段（旧条目读取时按 0/false 兼容），`tokens` 仍是本次实际记账数量。

- **`/phone quota`**：展示额度状态与窗口内「实际 usage 对账」明细——实际 usage 总量
  （输入未缓存/输入缓存/输出、对账次数）、尚未对账的估算量（运行中估算与 usage 缺失时的内部兜底估算），以及最近一次对账
  （实际、估算、补记、模型）。
- **`/phone quota audit [小时]`**：对照 AstrBot `provider_stats` 展示同会话窗口内模型
  实际用量与插件记账（不传小时时取 `quota.window_hours`，默认 24 小时；显式传参范围 1–168 小时），用于核对差异来源。

口径与边界：

- 只统计**手机相关 run**（手机工具/play/任务会话）；普通聊天不计入手机额度，AstrBot
  面板总用量包含普通聊天，两者口径不同；
- 既有记录不回溯补记，新 run 按实际 usage 对账；运行中看到的是估算值，run 结束后才对平；
- `provider_stats` 由 AstrBot 异步写入且仅覆盖 AstrBot 内部 agent：查询失败时降级为
  估算 + warning，第三方 runner/DB 异常时同样降级。

仅在额度启用且 `max_tokens>0` 时：达到 90% 工具结果尾部提示、用完拦截；仅在
`play_task_tokens>0` 时：预算完成后提示立即收尾。默认两者都不触发。

## 任务与媒体模型

所有模型在「任务与媒体模型」中直接选择已配置的供应商。按需要选择对应能力即可；
留空时按下表继承 AstrBot 的现有配置。

| 配置 | 用途与能力要求 | 留空行为 |
| --- | --- | --- |
| `model.provider_id` | 自主任务决策与工具调用，需要图片输入和 function calling | 使用任务会话的默认对话模型 |
| `model.vision_provider_id` | 屏幕 OCR、图片、图文正文、媒体关键帧与视觉验证，需要图片输入 | 图片描述模型，再使用当前会话模型 |
| `model.asr_provider_id` | 仅听音频、音频与关键帧链路、视频音轨单独识别时的 STT 转写 | 普通音频链路使用 AstrBot 当前 STT；视频音轨单独识别需显式选择 |
| `model.video_provider_id` | 接收带原音轨的 MP4，同时理解视频与声音，需要支持 video_url 的 OpenAI 兼容接口 | 使用音频与关键帧链路 |
| `memory.embedding_provider_id` | 聊天语义找回的向量模型 | 自动选择 AstrBot 默认 Embedding 模型 |
| `model.app_memory_embedding_provider_id` | App 操作经验的独立向量索引 | 继承聊天记忆向量选择，再自动选择默认 Embedding 模型 |

语音选择器列出 STT 模型，图片和视频选择器列出对话模型，向量下拉列出插件加载时可用的
Embedding 模型；新增向量供应商后重载插件刷新选项。聊天记忆与 App 经验可以共用一个
向量模型，索引与资料分别管理；未配置向量模型时 App 经验仍支持本地关键词查找。

视频模型默认同时识别原画面与声音，无需额外配置语音模型。只有需要独立转写音轨时才
开启 `model.video_audio_separate` 并选择语音模型；原视频与同时间窗转写一起发送，
声音内容以转写为准。`mode=audio` 使用语音链路，`mode=frames` 只理解画面。

`model.provider_id` 作用于持续刷手机、随机玩手机、`/phone play` 与静默后台任务。
用户对话和普通手动命令沿用当前会话模型；投递到用户会话的定时自主浏览也沿用该会话
默认模型。选择的任务模型不存在时记录 warning 并回退默认模型。

原生配置页保存后由框架重载，后续请求按当前选择执行。已有模型选择在加载前自动归组，
原配置保存在同目录的 `.models-backup` 文件；已有图片选择以媒体画面模型优先，其次 OCR 模型。

## 聊天记忆与按喜好分享

插件用 `event_message_type(ALL)` 记录最近聊天到
`plugin_data/astrbot_phone_control_mirror/chat/chat_memory.jsonl`（跳过空文本、`/` 开头命令、
机器人自己与 cron 事件；全局 3000 条、单会话 100 条）。`phone_recent_chat` 返回当前
（或指定 umo）会话最近消息与可分享会话列表，`phone_share_to_user` 支持 `target` 指定

## 控制/感知后端（ADB 兜底）

`control` 卡片选择控制层，`perception.screen_source` 选择感知帧来源；两者都保留 ADB
兜底，默认配置无需额外依赖即可运行。

| 后端 | 用途 | 说明 |
| --- | --- | --- |
| ADB（DeviceActions） | 控制 + 感知（兜底） | 默认可用；截图/点击/滑动/输入/按键全部可用 |
| scrcpy v5.0.1 | 控制 + 按需视频镜像 | `control.backend=auto/scrcpy` 时懒启动；默认仅控制通道（`video=false`，无 H264 编码/解码）；`perception.screen_source=auto/scrcpy` 时启用视频，raw H264 由 PyAV 实时解码成 JPEG 环形帧（无 PyAV 时回退 ffmpeg 管道） |
| DeviceFarmer/minitouch v1.3.2 | 可选 touch | 不随插件内置二进制；用户设置 `control.minitouch.binary_path` 指向 x86_64/arm64 可执行文件时启用，text/key 仍回退 ADBKeyboard/adb |

- 感知来源（`perception.screen_source`）：
  - `adb`（默认）：感知帧用 ADB 截图；scrcpy 只开控制通道，不做视频编码/解码，常驻开销低；
  - `auto`：**仅在 `perception.live_screen_enabled` 开启时**才启用 scrcpy 视频帧（可用则优先、过期或无帧时回退 adb）；持续截图关闭时等同 adb 感知，scrcpy 仅控制通道；
  - `scrcpy`：始终启用 scrcpy 视频帧（启动视频镜像；不可用时回退 adb）。
- 选型事实：scrcpy v5.0.1（2026-10，https://github.com/Genymobile/scrcpy）与
  DeviceFarmer/minitouch v1.3.2（2026-08，https://github.com/DeviceFarmer/minitouch）
  为当前采用版本；minitouch 官方无预编译产物，因此不打包。未采用
  openstf/minitouch、py-scrcpy-client、FRep；Ghost in the Droid、ai-auto-touch 仅作
  思路参考，不集成。
- 启动/降级：第一次需要控制或感知时才懒启动 scrcpy；server jar 默认用插件自带
  `bin/scrcpy-server-v5.0.1`，也可在 `control.scrcpy.server_jar` 指定；启动失败只告警
  一次并记录 `last_error`，自动回退 ADB。空闲 `control.scrcpy.idle_stop_seconds`
  （默认 120）无手机工具调用后停止连接（视频模式同时停止解码）；状态（`/phone status`、
  `phone_status`）会显示当前控制后端、感知后端、`scrcpy video` 可用性、能力与降级原因
  （帧不可用时静默回退 adb screencap，不向用户报错）。
- 路由：`phone_tap/long_press/swipe/input_text/key` 走控制后端（text 中文/失败回退
  ADBKeyboard）；`phone_screen(mode=image)`、`phone_screenshot`、`phone_live_screen`、
  `phone_read_screen` 走感知后端；设备状态/App 列表/UI dump 仍走 ADB（uiautomator）。
- 依赖：仅控制通道不需要 ffmpeg；启用视频镜像时需要运行环境安装 PyAV（`av`，
  wheel 自带 ffmpeg 库）或宿主机 `ffmpeg` 作为回退（`requirements.txt` 仅声明抓包所需的
  mitmproxy）。minitouch 需要用户自备与模拟器架构匹配的 binary。两者都不可用时功能与
  纯 ADB 完全一致。

## 控制/感知后端性能

AstrBot 容器 + 模拟器实测（scrcpy 停止态，交替多次取中位）：

| 操作 | 实测耗时 | 说明 |
| --- | --- | --- |
| uiautomator dump（`phone_screen` UI 树） | ≈2.5s（2.3–4.0s） | 感知主导延迟，也是「先看再点」的瓶颈 |
| ADB screencap（`phone_screenshot` / `mode=image`） | ≈0.6s | 默认感知来源 `adb` 的截图 |
| ADB `input tap` | 32–46ms | 裸注入本身很快 |
| ADB `input keyevent` | 38–45ms | |
| scrcpy 控制注入 `tap` / `HOME` | ≈21ms | 低延迟控制通道，与是否启用视频无关 |
| scrcpy swipe | ≈440ms | 与 ADB 一致，耗时来自系统手势动画 |
| scrcpy 启动（首次，仅控制通道） | ≈0.57s | 默认常驻；关闭常驻时空闲自动停止 |
| scrcpy 启动（首次，视频模式） | ≈0.7–1.0s | 视负载；视频镜像按需启用 |

结论：裸控制注入并不比 ADB 慢，主导延迟是 uiautomator dump；默认 `screen_source=adb`
时 scrcpy 只开控制通道，控制路径没有常驻 H264 编码/解码开销（视频镜像开启后设备侧
编码约 +7pp busy、容器解码约占 6–9% CPU，滚动时更高，因此默认不启用）。`text` / `desc`
定位复用最近一次 `phone_screen` 的 UI 快照（TTL 内有效，任何控制动作后失效），
把「先看再点」从两次 dump 降为一次。

## 任务转后台与实时屏幕

**任务转后台**：用户委托的多步手机任务（答题、找内容、发帖、评论、整理等）默认用
`phone_start_background_task(instruction, share_target="")` 转成静默后台任务——
`session` 为空、不投递过程消息，任务完成后由 AI 用 `phone_share_to_user` 汇报到当前会话
（或指定 target）。工具/命令立即返回，不等待完成。也可用 `/phone task <instruction>`，
`/phone tasks` 查看本插件创建的后台任务（job/状态/创建时间/摘要）。只有用户明确要求
「现在/实时/看着你操作」才在前台做；工具循环期间不要输出中间解说文字。
需要中止时用 `/phone stop [job_id|all]`：取消本插件创建的定时/后台任务（含正在跑的一轮），
同时关闭抓包、自主浏览调度、随机与持续任务并保存配置，停止实时屏幕与控制后端，回桌面强停应用。
桌面与当前输入法保持运行；清理失败会在命令结果中说明。需要抓包时用 `/phone traffic on`
重新开启；持续任务用 `/phone continuous on` 开启。

常驻子进程由插件每 3 秒发送心跳续租，本机监护器和手机端看门狗独立执行回收；插件失联
后最长约 18 秒结束子进程组或手机端服务，并恢复设备抓包代理。重载按代码指纹识别前任
租约，等待其释放资源后重建控制会话。

**实时屏幕（仅任务运行期间）**：`perception.live_screen_enabled`（默认 **false**：任务期间不再持续截图，
避免常驻 ADB 抓帧/解码拖慢手机；需要任务中快速取帧时再开启）表示
「玩手机/后台任务运行期间启用」，普通聊天不后台抓帧、不做后台识别。`LiveScreenWatcher`
只在任务会话（`phone_start_background_task`、`/phone play`、随机玩手机、持续刷）第一次
调用手机工具时懒启动，按 `live_screen_interval_ms`（默认 1200，限 300–5000）用自适应
截图抓帧，保存最近 `live_screen_frames`（默认 3，限 1–10）帧；抓图失败指数退避（最大 10s）
不中断且同一错误只记一次日志。任务结束（`on_agent_done`）或任务会话超过
`live_screen_idle_stop_seconds`（默认 90，限 30–600）没有手机工具调用时自动停止并清空
环形缓冲，不保留后台协程/抓帧；下次任务再懒启动。watcher 停止时两个工具仍可用（一次性
抓帧，不会启动常驻 watcher）。
- `phone_live_screen(wait_fresh_ms=0, include_image=true)`：返回最新帧的 age/前台
  App/Activity/截图 method，可把画面回传给主模型；`wait_fresh_ms>0` 保证帧新鲜
  （过期立即抓一张）。
- `phone_read_screen(prompt="", wait_fresh_ms=0)`：把最新帧交给 OCR/图片理解 Provider
  识别文字/数字/验证码。Provider 选择顺序：插件 `model.vision_provider_id` →
  AstrBot「图片描述 Provider」（`provider_settings.default_image_caption_provider_id`）
  → 当前会话 Provider；未配置/失败会返回明确 error 与建议（可改用 phone_live_screen）。
- 常驻开销：截图循环与工具操作共用一把锁串行抓图，不互相阻塞；interval 最小 300ms，
  adb 截图本身约 300–700ms，循环自然节流。

## 后台清理

后台保留名单为 `security.background_keep_packages`，默认包含 `com.wireguard.android` 与
`com.tailscale.ipn`。可在「权限与安全 → 后台清理保留名单」填写其他完整包名；填写列表后
按该列表保留，空列表仅保留桌面、输入法与系统入口。

| 触发 | 行为 |
| --- | --- |
| 浏览结束 | 按名单逐包清理，保留当前前台 |
| 任务收尾、`/phone stop` | 回桌面后清理第三方与最近任务 App，保留名单内应用 |
| `phone_clean_background` | 留空清理后台；指定包名时也检查保留名单及当前前台 |
| 抓包初始化 | 按同一名单重启应用，保留网络与输入服务 |

所有应用使用 `am force-stop --user current` 定向停止，清理前后核对进程并报告失败；
清理不删除 App 数据或登录状态。任务占用或验证暂停时按设备租约规则保留当前页面。

## 互动：主动评论 / 被动回复 / 发帖（AI 自主操作）

插件不提供「一键评论/发帖」工具，也不内置任何固定 App 点击流程；操作完全由 AI 用
`phone_screen` / `phone_tap` / `phone_input_text` / `phone_key` 等低层工具观察与完成。
插件只负责四件事：许可、限额、预约与记账。互动分三类：

| 类型 | kind | 触发场景 | 开关 / 限额 / 冷却 |
| --- | --- | --- | --- |
| 主动评论 | `comment` | AI 刷帖/看视频时自己想说点什么 | `security.allow_comments` / `max_comments_per_day`（默认 0=不限）/ `interaction_cooldown_seconds`（默认 0=不限，与发帖共用） |
| 被动回复 | `passive_reply` | 别人回复/评论了机器人，AI 读到后按心情与内容判断是否回 | `security.allow_passive_replies`（默认关）/ `max_passive_replies_per_day`（默认 0=不限）/ `passive_reply_cooldown_seconds`（默认 0=不限，独立冷却） |
| 发帖 | `post` | AI 在论坛类 App 分享有价值的内容 | `security.allow_posts` / `max_posts_per_day`（默认 0=不限）/ `interaction_cooldown_seconds`（与主动评论共用） |

- `phone_interaction_gate(kind="comment"|"passive_reply"|"post", app="")`：按 owner 门禁 →
  对应开关 → token 全局额度 → 对应每日上限 → 对应冷却（与最近一次**同冷却口径**的成功记录
  比较；被动回复只统计被动回复记录）的顺序校验，通过后预留一个名额。
- `phone_interaction_record(kind, success, summary, app="")`：AI 完成（或放弃）后记录结果；
  `success=true` 写入 `interactions.jsonl` 并计一次当日用量，`success=false` 释放名额、
  写失败记录但不计用量；未预约直接 record 会被拒绝。
- `/phone interactions [n]`：查看今日主动评论/被动回复/发帖次数、各自上限、冷却与最近记录
  （摘要截断）。
- 行为手册在 `skills/phone-interactions/SKILL.md`：只讲通用打法与边界（怎么找入口、
  如何校验发送成功、失败就停、绝不重复点发送），常见 App 入口仅作参考、不写死执行序列。
- 默认关闭；建议先保持关闭，待账号登录稳定、主人确认后再开启。每轮最多 1 条，不刷屏。

**主动评论**：有真实感触才发。先 `phone_interaction_gate(kind="comment")` 申请名额，再用
低层工具找评论入口、输入短内容、核对后**只点一次**发送，最后 `phone_interaction_record`
记录；失败就停下并如实说明。

**被动回复**：别人回复了机器人后，按下面的流程判断，不要逢回复必回：

1. 进入 App 先用 `phone_check_inbox` 看「回复我的 / 互动消息 / 私信 / 通知」；
2. 读实际回复内容，结合当前心情、人格与上下文判断值不值得回；
3. 不想回、内容有风险、看不懂或只是系统通知 → 直接跳过，**不申请名额、不占每日限额**；
4. 决定回复才 `phone_interaction_gate(kind="passive_reply")`，用低层工具输入并只点一次发送；
5. 用 `phone_interaction_record(kind="passive_reply", success=...)` 记录；
6. 被动回复有独立每日限额与独立冷却，不回复不刷屏，也不要用主动评论名额替代。

### 自主互动的决策与排查

随机、持续和定时自主任务都会收到当前评论、被动回复、发帖的授权状态与每日上限。开启对应 security 开关后，Agent 自行判断是否有表达内容；静默只约束向聊天汇报过程，App 内互动独立决定。`/phone interactions` 可查看授权、今日用量及实际记录。启用自主任务、对应权限和可正常执行工具的任务模型，是自主互动的前提；启用权限并不要求每轮发布。

对正文发表自己的评论，先理解正文，再 `phone_content decide(decision=comment,reason=具体感想)`；回复现有评论，则先 `read_comments`、读实际评论，再 `reply_comment(target=具体评论)`。之后均申请 `phone_interaction_gate(kind=comment)`，通过后操作，最后 `phone_interaction_record`。发帖使用 `kind=post`，回评使用 `kind=passive_reply`；评论、回评与发帖每轮合计最多一条，限额和冷却由名额申请实时检查。

## 进入 App 浏览新消息（收件箱）

`phone_check_inbox(app="", include_image=true, max_nodes=0)` 用于「进入 App 后先看新消息」：

- 通用识别当前 App 里的「消息 / 收件箱 / 回复我的 / 互动消息 / @我的 / 私信 / 通知」入口，
  能定位就点进去，回传该页 UI 树与可选截图；`app` 留空表示当前前台 App，也可填中文名 /
  别名 / 包名（会先打开再查）。
- 返回内容包括入口识别情况、消息列表文本与截图，供 AI 判断有没有人回复自己、要不要做被动回复。
- `phone_open_app` 打开成功后也会提示先 `phone_check_inbox`。每次进入 App 先浏览新消息，
  再决定浏览、互动还是跳过；没有新消息就按原计划自由活动。

## 持续刷手机与学习

选择 `auto.mode=自动刷` 并启用 `auto.activity_enabled`，或 `/phone continuous on` 开启后，插件自动一轮接一轮地
唤醒主 Agent 自由活动（浏览信息流、看视频、查收件箱、按需互动），直到关闭或 `/phone stop`：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `auto.continuous_gap_seconds` | 60 | 两轮之间的间隔秒数（10–3600） |
| `auto.continuous_target_tokens` | 0 | 每轮目标 token 预算（0=使用 `quota.play_task_tokens`） |
| `auto.continuous_apps` | 空 | 偏好 App，逗号分隔（如 `douyin,bilibili`）；空=AI 按人格自选 |

- 每轮结束前用 `phone_learn(content, source="", tags=[])` 记录 **1–2 条真正学到的内容**
  （看到的知识、App 用法、用户/群喜好等），不要记流水账；环境里有 `memorize_long_term_memory`
  等长期记忆工具时也写入。
- **理解并记录，不是空刷**：刷到内容要读标题/正文/评论并理解（观点、知识点、梗、事件、
  社区规则），不要只滑；每 3–5 条或约 5 分钟用 `phone_learn` 记一次真正理解到的点，
  一轮结束前至少记录 1 条。
- 学习档案会注入后续提示词（最近学到），下一轮开始时会看到并可主动温故，避免「刷完就忘」。
- **归属**：持续刷/随机玩/定时自主浏览等自行唤醒学习不计入用户记忆；用户指定使用手机（会话中让你刷、`/phone browse`、`/phone task` 等）的学习计入发起用户信息；面板「学习记录」会标注归属。
- `/phone learn [关键词|条数]` 查看学习档案：关键词做检索；数字 1–30 看最近 N 条；
  留空看最近 8 条。学习档案落在插件数据目录（`learning.jsonl`），最近条目还会注入
  后续提示词（`【最近学到】`），供后续轮次与主动分享参考。
- 也可在插件面板「学习记录」页查看与检索：关键词匹配内容/来源/标签（大小写不敏感），
  条数可选 20/50/100/200；顶部显示总条数、来源分布、最近记录时间与档案上限（默认 2000 条环形），
  空档案会提示如何生成记录。
- `/phone continuous on|off|status [间隔秒] [token预算]` 控制持续刷并查看当前状态
  （是否运行、下一轮时间、间隔、预算、偏好 App、学习条数）。`off` 只是不再开新轮，
  当前这一轮会自然跑完；要立即停下用 `/phone stop`。
- `/phone stop [job_id|all]` 立即停止：取消本插件创建的定时/后台任务（含正在跑的一轮）、
  停实时屏幕 watcher 与 scrcpy 连接，并 HOME 回桌面、按保留名单清理后台。
- 持续刷是**静默**的：不逐轮向聊天汇报；有真正值得说的再 `phone_share_to_user` 分享一次。

## 浏览日志（自动清理与保护轮次）

每次浏览、自主任务或持续刷手机都会把采集到的内容写入浏览日志（`diary/diary.jsonl`），
用于聊天汇报与提示词注入。日志默认最多 500 条，达到上限自动清理最旧的日志：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `browse.diary_max_entries` | 500 | 日志条数上限（10–100000）；达到上限自动清理最旧日志 |
| `browse.diary_protect_rounds` | 3 | 清理时保护最近 N 轮任务的日志（0–100，0=不保护） |

- **一轮任务**：一次 Agent 任务（用户手机任务、自主浏览、随机/持续刷、后台任务）或一条
  `/phone browse` 命令算一轮；同一轮内多次浏览的日志共享同一轮次编号。
- **保护语义**：最近 N 轮任务的日志不会被清理，即使这些轮次的日志总量已经超过上限
  （例如上限 100、保护 3 轮，这 3 轮的日志合计 150 条也全部保留）；下一轮开始后更早的轮次
  才按上限淘汰。
- 清理在上限配置保存/插件启动/写入新日志时执行；旧版本没有轮次标记的日志按普通旧日志处理。
- 面板「浏览日志」页可分页查看与搜索；聊天里用 `/phone diary [条数|关键词]` 查看，
  AI 用 `phone_recall_diary` 检索。

## 人机验证 / 做题（phone_solve_verification 与 phone_bypass_verify）

遇到滑块、顺序点击、识图、拼图、答题/测试页时，优先用 `phone_solve_verification`：

1. 工具内部先快速截图，**第一次视觉模型调用**返回图片内容摘要、是否人机验证、验证类型
   （slider / sequence / image_click / puzzle）与是否答题/测试页；
2. 如果确实是人机验证或做题，**重新截图并第二次调用视觉模型**，要求给出操作顺序
   （点击序列或拖拽轨迹）与最终确认点（提交/下一题按钮）；
3. 工具按顺序自动执行这些操作与确认点，再截一张图返回执行摘要，全程一次工具调用完成，
   不需要主模型反复截图/dump。

参数：`mode=auto|captcha|quiz`（默认 auto，可明确按验证码/做题处理）、`include_image`、
`timeout_seconds`（0 表示取 `perception.verify_timeout_seconds`，再回退
`perception.ocr_timeout_seconds`）。适合滑块、顺序点击、识图、拼图、答题与测试页；
视觉 Provider 不可用、超时或识别失败时，回退 `phone_bypass_verify` 手动完成：
先 `capture` 快速截图看类型，再用 `drag` / `tap_points` / `slide` 一次手势解决。

| `phone_bypass_verify` action | 用途 |
| --- | --- |
| `capture` | 快速截图（不跑 uiautomator dump，约 0.6s 级），先看清验证类型与滑块位置 |
| `drag` | 按坐标拖拽/滑块一次完成（`x1,y1,x2,y2`，可指定 `duration_ms`） |
| `tap_points` | 顺序点击验证：一次调用按 `points` 依次点击多个点（`interval_ms` 控制间隔） |
| `slide` | 自动定位滑块并拖到最右，适用于标准横向滑块 |

不要反复 `phone_screen(mode="ui")`（每次 uiautomator dump 要 2~13s）或 `phone_wait` 空等；
操作一次后校验，失败就停并如实汇报，交给用户处理。完整手册见
`skills/phone-verification/SKILL.md`。

## 做题 / 测试页优化

当工具结果出现验证/答题提示时（`phone_screen` 返回「检测到答题/验证页面」，`phone_check_inbox`
返回「当前页面可能有人机验证/答题」），说明当前页面有答题、测试、验证或问卷特征：

- 优先调用一次 `phone_solve_verification(mode="quiz")`：它直接读题、给出选项点击顺序与
  提交/下一题确认点并自动执行，比主模型多轮「截图→想→点」快得多；
- 需要精细控制（例如想先看题目再决定、或 solver 识别失败）时，用
  `phone_bypass_verify(action="capture")` 快速截一张图，看懂后一次性 `tap_points` 完成，
  不要反复 `phone_wait` / `phone_screen` 干等；
- 逐题推进时每做完一题再截一张图确认页面变化，避免在旧坐标上连续点击；
- 短信/邮箱验证码、人脸核验、实名信息仍交给用户处理，不要尝试绕过。

## 心情与记忆来源

插件不另建「心情」存储，AI 的情绪与选择由这些上下文共同决定：① AstrBot 人格/persona；
② `phone_recall_diary`（浏览/玩手机记忆）；③ `phone_recent_chat`（最近聊天与群喜好）；
④ 学习档案（`phone_learn` 写入、`/phone learn` 查看，最近学到会注入后续提示词）；
⑤ 环境里若有 `recall_long_term_memory` 长期记忆工具则先回忆；⑥ 浏览/玩手机结束时可
调用 `memorize_long_term_memory` 写入长期记忆。

## 性能与简洁回复

- **scrcpy 预热**：手机相关 LLM 请求（play/后台任务、白名单关键词或工具已激活）且
  控制/感知配置需要 scrcpy 时，后台预热（60 秒最多一次，不阻塞 LLM），减少首次启动
  等待；感知来源为 `adb` 时预热不启用视频镜像。
- **精简 schema / 提示词**：38 个 phone_* 工具的描述与参数描述在注册时压缩（不改变工具
  名/参数名/行为）；guidance 压缩到 ≤320 字（含互动提示 ≤420 字）；默认
  `perception.max_ui_nodes=80`、`max_text_len=60`、`control.scrcpy.max_size=720`，
  减少模型输入与按需视频解码开销。
- **等待与验证超时可配置**：`phone_wait` 不传 `seconds` 时取
  `perception.wait_default_seconds`（默认 2s），单次等待硬上限
  `perception.wait_max_seconds`（默认 60s，面板可调）；`phone_solve_verification` 每次
  视觉模型调用超时 `perception.verify_timeout_seconds`（默认 30s）。
- **简洁回复**：guidance 与 skill 明确要求默认 1–2 句、≤80 字；任务结果只给 1–3 个
  要点，不复述过程/工具输出（用户要求详情除外）。随机玩/后台任务的汇报提示词同样
  带有该约束。

## WebUI Dashboard（监控与资料管理）

插件页面：`/#/plugin-view/<插件标识>/dashboard`，页面导航含「监控面板」、「Relay App」、「浏览与学习」、「记忆索引」、「组网接入」和「保存的图片」：

- **监控面板**：**概览卡片**（版本/运行时长/后端状态/额度/今日互动/最近截图与 LLM 指标）、
  **截图耗时曲线**、**LLM Token/s 曲线**与**最近抓包预览**。
- **浏览日志**：分页查看浏览/自主任务写入的日志（最新在前），支持按内容、App、备注搜索；
  顶部显示总数、上限、保护轮次、最近时间与 App 分布，不返回截图绝对路径。
  日志达到上限自动清理旧日志，最近 N 轮任务的日志受保护。ADB 未启用（假开启）时也可只读访问。
- **学习记录**：查看与检索 AI 在手机上学到的内容（`phone_learn` 写入
  `plugin_data/astrbot_phone_control_mirror/learning.jsonl`）。顶部统计总条数、来源分布（取前几个）、
  最近记录时间与档案上限（默认 2000 条环形）；列表最新在前，展示时间（`YYYY-MM-DD HH:MM`）、
  来源、内容、归属（自行唤醒/用户指定）与标签，空档案显示引导提示；支持关键词检索（内容/来源/标签，大小写不敏感）、
  条数选择（20/50/100/200）、手动刷新与确认删除。删除按唯一编号执行；本地档案中的记录删除后，已同步到记忆插件的副本由记忆插件管理。
- **保存的图片**：按语义、理由、标签、来源或编号检索，30 张一页。点击「查看图片」读取原图；
  仅存手机时需连接保存时的同一设备，手机执行任务时稍后重试。支持编辑语义（1–500 字）、
  保存理由（最多 500 字）、标签（最多 10 个，各 40 字）和图片/表情包类型；保存后即时生效。
  删除需确认，移除图片库记录及服务端原图，手机相册副本由手机管理。

页面通过插件 Web API（路由前缀 `/{插件标识}/dashboard/`）读取数据，视图由
`views/dashboard/` 提供，后端只按冻结契约返回数据：

| 方法 | 路由 | 说明 |

| GET | `dashboard/overview` | 版本/运行时长/后端状态/额度/今日互动/抓包状态与最近流量/最近截图与 LLM 指标 |

资料管理 API 由 AstrBot 面板统一登录认证；配置修改见「配置修改与热应用」。

指标落盘 `plugin_data/astrbot_phone_control_mirror/metrics.jsonl`（环形上限 20000 行）：
截图 `{ts,kind:"screenshot",ms,source,method}`；LLM `{ts,kind:"llm",tokens,ms,tps,session}`。
LLM 指标按**每次 LLM 调用**采样：中间轮在工具调用边界记录本轮**输出 tokens 估算**
（工具调用参数）与真实墙钟耗时；Agent 结束时用最终 response 的真实 `usage.output` 校正。
`tps = 输出 tokens / 调用耗时`（与模型生成速度同量级，输入上下文不计入 token/s）；
10s 桶按调用耗时加权，面板秒级轮询后曲线近实时更新。

## 配置修改与热应用

插件配置修改有两类入口：

- **AstrBot 原生插件配置页**：框架保存后重载插件，所有组件按新配置重新构造；
- **`/phone` 命令族内的补丁**（如 `/phone continuous on|off`、`/phone traffic on|off`、
  `/phone stop` 关闭持续刷）：插件不能重启自己，命令会先把补丁持久化到配置，再把运行态
  变化同步应用到已经启动的组件。新增配置项必须归入 `core/config_apply.py` 的
  `LIVE_KEYS`（每次使用实时读取）或 `RECONCILE_KEYS`（需要重建/重启组件）之一，
  `tests/test_config_apply.py` 会检查分类完整性，避免新增配置项出现「保存了但没生效」。

保存配置补丁后立即处理的运行态配置：

| 配置 | 保存后的行为 |
| --- | --- |
| `auto.mode` / `auto.activity_enabled` | 互斥选择随机玩、自动刷或定时玩；关闭或切换后中止对应自主任务 |
| `perception.live_screen_enabled` | 关闭时立即停止 watcher；开启时若有运行中任务立即启动，否则下次任务生效 |
| `auto.random_*` | 按新间隔/概率重新计算下一次触发时间 |
| `auto.mode=定时玩` / `cron` / `apps` / `session` / `max_items` / `prompt` | 按新配置同步自主浏览 cron 任务 |
| `control.*` / `perception.screen_source` | 重置当前控制/感知后端会话，下次手机操作按新配置重建 |
| `adb.host/port/path/serial/超时` | 断开旧目标并按新参数重配，下次手机操作连接新设备 |
| `model.provider_id` | 后续自主任务请求使用新 Provider；用户对话继续用默认模型 |
| `traffic.enabled/port/body_chars` | 开关/端口/正文长度变化时停止后按新配置重启抓包 |

其余配置项（权限/媒体识别/额度/模型选择/浏览/等待/截图/提示词/调试等）每次使用时
实时读取；通过 AstrBot 原生插件配置页修改时，则在保存重载后全部按新配置生效。

## App 使用经验（记忆）

AI 使用 App 时把布局与使用方式沉淀为可复用经验，后续先按经验查找/操作：

- `phone_app_memory(app, page?)` 查经验：返回该 App 记住的页面、布局/入口说明、操作
  步骤与使用次数；
- `phone_app_remember(app, note, page?, steps?)` 记录/更新经验：同一 App + 页面再次记录
  会覆盖为更高版本（App 改版后重新探索并用它更新）；
- 本轮请求会以临时内容块注入最近更新的 App 经验摘要（`prompt.app_memory_enabled`、`prompt.app_memory_limit`
  控制，默认开/最多 5 个 App）；`phone_open_app` 打开 App 后也会附带该 App 的经验提示；
  App 经验、浏览日志、学习档案与新鲜感状态只对授权用户的手机任务/手机请求注入，普通对话
  与非主人请求不注入；
- 经验只保存在 `plugin_data/astrbot_phone_control_mirror/app_memory.json`，容量上限 500 条，
  按最近更新淘汰；记录、查询与注入共用这一份本地档案。
- 语义召回使用独立索引 `plugin_data/<插件标识>/semantic_app/` 与独立向量模型配置
  `model.app_memory_embedding_provider_id`（留空继承聊天记忆选择，再使用默认 Embedding Provider），
  与聊天语义找回的索引、资料独立管理，模型选择可共用；未配置向量模型时按页面关键词与更新时间兜底。
- 经验以当前屏幕为准。`phone_open_app`、`phone_screen`、`phone_read_screen`、
  `phone_check_inbox`、`phone_content` 返回后会自动追加「按当前 App/页面召回」的经验
  （同一轮同一页面只召回一次）；`phone_tap`/输入/滑动/切换等操作报错时，本轮召回的
  经验累计失败次数，连续两次标记为「可能已失效」并提示重新探索后用
  `phone_app_remember` 覆盖更新；覆盖成功后版本 +1 并清除失效标记。

## 记忆存储去向（本地 / MemoryCompanion / LivingMemory）

`memory` 卡片控制学习档案的保存位置与同步去向；学习档案默认保存在插件本地，供 `/phone learn` 查询：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `memory.local_enabled` | 开 | 保存到插件本地（学习档案、浏览日志、聊天记忆）；关闭后不再写入本地，依赖本地记忆的聊天语义找回同时停用并隐藏配置 |
| `memory.companion_enabled` | 关 | 开启后学习记录同步到 MemoryCompanion |
| `memory.livingmemory_enabled` | 关 | 开启后学习记录写入 LivingMemory；可与 MemoryCompanion 同时开启 |
| `memory.companion_user_id` | 空 | 仅在开启 MemoryCompanion 时显示；同步绑定的用户 ID，留空时用户会话用发送者 ID、自刷任务用 `security.owner_ids[0]` |
| `memory.bot_action_enabled` | 关 | 仅在开启 MemoryCompanion 时显示；自行唤醒学习是否额外以「个人记忆-行动」记入一份，默认不计 |

- 本地存储关闭后，学习档案、浏览日志与聊天记忆不再落本地，`/phone learn`、浏览日志与聊天记忆列表不再新增数据；已有本地文件保留但不读写。
- 未选中 MemoryCompanion 时，`companion_user_id` 与 `bot_action_enabled` 不显示（配置页按 `condition` 显隐，隐藏字段仍保留已保存值）。

- **归属规则**：`attribution=autonomous`（自行唤醒：持续刷/随机玩/定时自主浏览）的学习记录只写本地档案，不计入 MemoryCompanion/LivingMemory 用户记忆；`attribution=user`（用户指定使用手机：普通会话工具、`/phone browse`、用户发起的 `/phone task` 与 `/phone play`）计入发起用户（后台任务取 `requested_by`，回退发送者/`companion_user_id`/`owner_ids[0]`）。
- `memory.bot_action_enabled` 只对自行唤醒学习生效：开启后额外用「个人记忆-行动」记入 MemoryCompanion 一份，仍不写用户记忆。
- MemoryCompanion 通过其公开桥接 `get_memory_companion_bridge().record_external_memory`
  写入用户长期记忆；开启 `bot_action_enabled` 时再用 `record_bot_action` 记一条 Bot
  行动记忆（个人记忆 → 行动）。
- LivingMemory 通过插件实例的 `memory_engine.add_memory` 写入；LivingMemory 未安装/未启用
  或未就绪时工具结果会如实提示并保留本地记录，不丢数据。
- 未安装对应记忆插件时自动降级为本地存储并在工具结果中说明。

## 聊天语义找回（recall）

该能力依赖插件本地记忆：`memory.local_enabled` 关闭时整张「聊天语义找回」卡片不显示、
索引维护与聊天注入同时停用。

`recall.enabled`（默认关闭）开启后，插件把**学习档案**、**浏览日志**与**App 使用经验**
建成插件本地向量索引（`plugin_data/<插件标识>/semantic/`，manifest + entries + vectors
两代原子切换）；普通聊天时按当前消息语义检索相关记忆，作为本轮临时内容块注入：

- **只读本地记忆**：注入路径不持有设备服务，不连接 ADB、不预热 scrcpy、不创建后台任务；
  ADB 未配置（假开启）时同样可用。
- **只对普通私聊生效**：任务/定时/自主浏览、群聊与命令不注入；默认仅授权用户。
- **注入方式**：`req.extra_user_content_parts` 追加临时 `TextPart`，标题为「【相关记忆】」；
  不修改 `system_prompt`、不写入会话历史；同一请求不重复注入。
- **索引维护**：插件启动空闲后后台构建，学习/日志写入后防抖增量更新，并按
  `recall.refresh_minutes` 周期检查；构建失败指数退避且只告警一次，索引损坏自动重建，
  构建失败不影响聊天与插件其他功能。关闭记忆本地保存后不再构建索引。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `recall.enabled` | 关 | 总开关 |
| `memory.embedding_provider_id` | 空 | 向量模型 Provider ID；留空自动选 AstrBot 默认 Embedding Provider，找不到时跳过找回并告警一次 |
| `recall.top_k` | 5 | 注入条数上限（1–20） |
| `recall.min_score` | 0.25 | 最小余弦相似度（0–1） |
| `recall.max_chars` | 1200 | 注入文本字符上限 |
| `recall.index_max_docs` | 2000 | 索引最多文档数（超出按时间保留最近） |
| `recall.doc_chars` | 300 | 单条文档截断字符数 |
| `recall.timeout_seconds` | 3 | 普通聊天查询向量与检索的总超时 |
| `recall.refresh_minutes` | 10 | 周期检查/增量刷新间隔 |
| `recall.include_diary` / `include_learning` | 开 | 索引数据来源开关（学习档案 / 浏览日志） |

- 需先在 AstrBot 配置可用的 **Embedding Provider**；App 使用经验使用独立索引与
  `model.app_memory_embedding_provider_id`，不进入聊天找回索引。
- 隐私：索引与注入文本只保存在插件数据目录/当轮请求中；群聊默认不注入。

## 设备执行入口与占用

命令、LLM 工具与定时自主任务接触设备前统一经过插件内的设备执行入口：

- **授权**：先校验 `security.owner_ids` / 管理员 / 白名单，再做抢占、提示词注入、后端预热等副作用；
- **占用**：一次 Agent run 或一次命令处理持有设备租约（同一事件内可重入）；其他任务在租约释放前收到「手机正被另一个任务使用」提示，用户任务优先时撤销自主任务租约并递增取消代次；
- **暂停**：验证处于 `awaiting_user` / `checking` / `expired` 时拒绝自动写操作；`expired` 不会自动解除，必须 `/phone verify cancel <id>` 释放；
- **取消代次**：暂停、停止、抢占会递增取消代次，正在执行的工具动作批次与在途求解在下一次检查时立即中止；
- **期限**：验证类执行取「会话剩余时间」与「单次尝试剩余时间」的较小值，`attempt_timeout_seconds` 到点由看门狗收口为人工协助并取消在途求解；
- **持久化故障**：`verification.json` 写盘失败时 fail-closed——拒绝所有设备操作并停止自动循环排程，写盘恢复后自动解除；
- 实时屏幕、抓包、媒体采集、scrcpy 等后台基础设施不持有设备租约，只做采集/维护，不参与任务决策。

## 验证与人工协助（有限自动尝试 → 暂停并求助）

人机验证/做题页面不再无限重试：`verification` 卡片控制自动尝试与人工接管策略。

- `verification.max_attempts`（默认 3）：自动尝试中允许的**失败/无法确认次数**上限；`0`=直接请求人工协助（不是无限重试）。答题的逐题推进不计入失败次数。
- `verification.total_timeout_seconds`（默认 120）：从进入验证开始累计的自动处理总时限；失败次数或时间先到者生效。
- `verification.attempt_timeout_seconds`（默认 30）：单次尝试从取图到结果观察的时限；到点由看门狗取消在途求解并转人工协助，看门狗每 5 秒检查一次。
- `verification.manual_wait_timeout_seconds`（默认 600）：等待用户协助时限；到期后进入 `expired`，任务结束但设备保持暂停，必须显式 `/phone verify cancel <id>` 才解除。
- `verification.notify_target`：自主任务的求助通知会话 UMO；用户任务优先回发起会话，留空时回退最近交互会话。

行为：

- `phone_solve_verification` / `phone_bypass_verify`（非 capture）与验证期间的普通写操作共享同一会话预算；
  进入验证后普通 `phone_tap/swipe/input/key` 等写操作会提示改用验证工具，不能换工具绕过次数。
- 结果判定：执行动作后读取 UI 文本形成结构化结果——挑战已解除 / 答题进度（换题即进度，不累计失败）/
  未通过（失败词或挑战仍在）/ 无法确认（观察失败，fail-closed 计入失败）。
- 失败次数或时间耗尽 → 持久化 `awaiting_user`、暂停手机自动操作、停止实时采集、**不 HOME/不清后台**，
  由程序（不依赖模型）发送一次确定性求助通知；通知失败有界重试并保持暂停。
- 进入暂停时会递增取消代次并撤销设备租约：正在执行的求解器与动作批次在下一次检查时中止，不会继续点击。
- `/phone verify status` 查看会话（含失败次数、答题进度、本次尝试剩余时间）；`/phone verify resume <id>`
  用户完成验证后先做一次有界观察，通过才解除暂停；`/phone verify cancel <id>` 取消等待并释放暂停；
  `/phone stop` 同时取消验证等待。`expired` 状态只能 `cancel` 释放，`resume` 会被拒绝。
- 状态写入插件数据目录 `verification.json`（原子写）；写盘失败时 fail-closed：拒绝设备操作并停止自动
  循环排程，写盘恢复后自动解除。插件重载/容器重启后保持暂停（含 `expired`），不会自动重跑旧验证。
- 状态**读取**失败（文件损坏、类型/结构异常、读取无权限）同样 fail-closed：保留原文件不覆盖不删除，
  拒绝全部设备操作并在 `/phone verify status` 提示原因；确认不需要保留原状态后发送
  `/phone verify cancel <任意编号>` 显式处置（坏文件改名保留为 `verification.json.corrupt-*`），
  `/phone stop` 不会静默清除该故障。
- 群/私聊通知目标由配置或发起会话固定，不按最近聊天随机选择；求助通知独立于分享免打扰/每日限额。

## 手机流量抓包识别（页面内容优先来源）

插件可在**手机上对手机流量抓包**（不是直接调用 App API）：容器内运行 mitmproxy，通过
`adb reverse` 把手机代理指到 mitmproxy，并在手机上注入系统 CA 解密 HTTP(S) 流量；解密后的
接口 URL、状态码与响应 JSON/文本会写入抓包日志，供 `phone_traffic` 工具读取，用来识别当前
App 页面与内容（信息流/详情/评论区/搜索等）。

- **协同方式（自动）**：`phone_screen` 在抓包可用时会自动附带「当前页面抓包内容」——只取
  当前前台 App、最近一次手机操作之后、未过期（默认 90 秒）的接口；同一页面只保留最新一条，
  并标注最新流量年龄与回退原因，模型不必再先单独调 `phone_traffic`。图文、视频画面、布局等
  视觉信息仍看截图/OCR；抓包不可用、不属于当前 App 或已过期时自动回退屏幕识别；需要原始流量
  明细（`scope=recent`）或可分享链接时再用 `phone_traffic`（默认 `scope=page` 只取当前页面）。
  抓包不能完全代替多模态。
- **运行前提**：宿主可执行 `mitmdump`。系统 CA 模式需要手机支持 `adb root`，用于 CA 绑定挂载与 `nsenter`；
  手动 CA 模式由设备或应用自行信任证书，HTTP 抓包可直接使用。抓包依赖通过独立 venv 管理：
  ```bash
  python3 -m venv /AstrBot/data/plugin_data/astrbot_phone_control_mirror/traffic/venv
  /AstrBot/data/plugin_data/astrbot_phone_control_mirror/traffic/venv/bin/pip install mitmproxy
  ```
  然后在插件配置 `traffic.mitmdump_path` 填写该 venv 的 `bin/mitmdump` 绝对路径；
  也可把该路径加入容器 PATH，留空时插件按 PATH/当前 Python 同目录查找。插件不自动安装
  mitmproxy，缺失时只提示并禁用抓包，不影响其他功能。
- **配置**：`traffic.enabled`（默认开）、`traffic.port`（默认 18080）、
  `traffic.body_chars`（响应正文截断，默认 1200）、`traffic.keep_seconds`（默认窗口 900 秒）、
  `traffic.mitmdump_path`（可选 mitmdump 路径，默认空）。
- **隐私**：抓包日志只保留最近流量、正文截断、URL 敏感参数打码；日志位于插件数据目录
  `traffic/flows.jsonl`，可随时删除。
- **可见性**：`/phone traffic [status|tail [n]|on|off]` 查看抓包状态/最近流量或开关；
  Dashboard 概览的抓包预览区展示抓包状态与最近流量；抓包运行期间 AstrBot 日志每 5 分钟
  输出运行摘要与最近流量可读信息（时间、方法/URL、状态码、页面推断、响应片段、可分享链接，
  URL 敏感参数打码，见「抓包信息日志」）；完整明细在插件数据目录 `traffic/flows.jsonl`
  （容器内 `/AstrBot/data/plugin_data/astrbot_phone_control_mirror/traffic/flows.jsonl`）。
- **注意**：抓包启动时会结束已运行的第三方 App（保证新进程信任注入的 CA）；之后新启动的
  App 才能被解密。评论区/被动回复一开始必须用 UI 确认回复对象（用户/楼层），不要只凭抓包
  记录直接调接口；熟悉流程并积累抓包记录后才可逐步参考请求格式用 API 发送回复。
  停止插件/关闭抓包时会恢复设备代理与 CA 挂载，避免设备断网。
- **不可用与重试**：设备无 root、系统证书绑定挂载被拒绝、容器缺少 mitmdump 等确定性不可用时，
  只记录一次明确原因并停止自动重试（`/phone traffic` 与工具状态可看到原因），避免反复操作设备；
  临时失败（adb 抖动、端口暂被占用等）按 30 秒起指数退避重试，连续多次失败后同样收敛为不可用，
  修改抓包配置或重新启用会清除不可用状态并重新尝试。插件重载会先停掉旧实例的抓包，不会出现
  多实例同时操作同一台设备。

## 抓包信息日志

抓包运行期间，插件把最近流量的可读摘要写入 AstrBot 日志，无需额外操作即可确认当前抓到了什么：

- **频率**：每 5 分钟输出一次（后台保活循环每 90 秒检查，距上次输出满 300 秒才打印）。
  先一条运行摘要，如 `抓包：运行中（端口 18080，已记录 42 条，近 5 分钟 7 条）`。
- **最近流量**：随后最多输出 3 条最近流量的可读信息，每条包含
  - 时间、方法与打码后的 URL、状态码、页面推断（如 `B站·视频详情`）；
  - 响应正文片段（按 `traffic.body_chars` 截断，日志里最多 600 字）；
  - 可分享链接（从响应中提取，最多 3 个）。

  日志逐行形如：

  ```
  抓包：[12:34:56] GET https://api.example.com/feed?page=1&token=*** → 200 | B站·首页推荐
  抓包：  响应：{"data":[{"title":"…"}]}…
  抓包：  可分享链接：https://www.bilibili.com/video/BV1xx411c7mD
  ```

- **打码与截断**：URL 查询参数中的敏感字段（`token`、`key`、`sign`、`session_id`、
  `password` 等）值替换为 `***`；响应正文只输出截断片段。
- **完整明细**：仍在插件数据目录 `traffic/flows.jsonl`（容器内
  `/AstrBot/data/plugin_data/astrbot_phone_control_mirror/traffic/flows.jsonl`），
  `phone_traffic` 工具与 `/phone traffic [status|tail [n]|on|off]` 读取的就是它；
  日志只是摘要，完整查询用工具或命令。

## WireGuard 组网（client / server 与 ADB over WG）

AstrBot 容器没有 `NET_ADMIN`、`/dev/net/tun` 与 `ip`/`wg` 工具，无法使用内核 WireGuard。
插件随包分发 Linux x86_64 的 userspace helper（`bin/linux-x86_64/phone-wg`；wireguard-go + netstack）；
其他平台可按本仓库 `helper/phone-wg` 源码自行编译后放到插件根目录 `bin/phone-wg`。
helper 由插件按配置以子进程启动并管理：密钥由插件生成（X25519 + WireGuard clamp），helper 在
用户态建立 WG 接口，并按 `forwards` 做 TCP 端口转发。两种角色：

| 角色 | 插件做什么 | 对端做什么 |
| --- | --- | --- |
| `client` | 连接已有 WireGuard 服务器，经隧道访问手机 | 对端在 WG 服务器上登记手机/插件 peer |
| `server` | 监听 UDP `listen_port`，手机作为 peer 接入，自动生成手机密钥 | 手机安装 WireGuard App，导入 `/phone wg config` 输出的配置 |

### client 模式（连接已有 WG 服务器）

1. 插件配置：
   - `network.enabled = true`；`network.provider = wireguard`；
   - `network.wireguard.mode = client`；
   - `network.wireguard.server_endpoint = <服务器地址>:<端口>`（如 `192.168.250.50:51820`，必填）；
   - `network.wireguard.server_public_key = <服务器公钥>`（必填）；
   - `network.wireguard.interface_address`（默认 `10.66.0.2/24`）与 `network.wireguard.phone_wg_ip`
     （默认 `10.66.0.3`，手机在 WG 网内的地址）；
   - 可选 `network.wireguard.preshared_key`、`network.wireguard.adb_local_port`（默认 15555）、`network.wireguard.auto_adb`。
2. 保存配置后插件启动 helper；`/phone wg config` 输出服务器侧需要添加的 Peer 片段
   （含插件公钥、可选 PSK、`AllowedIPs = 10.66.0.2/32`），把它加到 WG 服务器配置里。
3. ADB over WG：`adb_local_port > 0` 时 helper 监听 `127.0.0.1:<adb_local_port>` 并转发到
   `phone_wg_ip:<adb_target_port>`；`auto_adb=true` 时插件在 helper 就绪后把 ADB 目标切到
   `127.0.0.1:<adb_local_port>`（停止/异常/配置变化时自动恢复原目标）。不开启 `auto_adb`
   时可按需手动使用该本地端口。官方 WireGuard App 手机使用 Phone ADB Relay，
   `adb_target_port=15555`；Linux/root 全局隧道可使用直接 adbd 端口。

### server 模式（手机作为 WG 客户端接入）

1. 插件配置：
   - `network.enabled = true`；`network.provider = wireguard`；`network.wireguard.mode = server`；
   - `network.wireguard.listen_port`（默认 51820，UDP）；
   - `network.wireguard.public_endpoint`（必填）：手机侧可访问到本插件 WG server 的地址，
     如 `192.168.250.50:51820`；只填 host 时端口取 `listen_port`；
   - `network.wireguard.interface_address`（默认 `10.66.0.1/24`）、`network.wireguard.phone_wg_ip`
     （默认 `10.66.0.2`，手机在 WG 网内的地址）；
   - 可选 `preshared_key`、`adb_local_port`、`auto_adb`。
2. 保存后 `/phone wg config` 输出**手机端完整 WireGuard 配置**（含手机私钥、Address、
   服务器公钥、Endpoint、AllowedIPs、PersistentKeepalive），复制到手机 WireGuard App
   导入即可；手机密钥由插件自动生成并保存在 `wireguard/keys.json`。
3. 端口暴露：AstrBot 容器没有对外映射 UDP 端口时手机无法直连容器内 helper。可在 AstrBot
   所在网络用 UDP relay/端口转发（例如把宿主 `51820/udp` 转发到 AstrBot 容器 `51820/udp`），
   或按平台方式为应用增加 UDP 端口映射；`public_endpoint` 填手机实际能访问到的地址。
4. ADB over WG 与 client 模式相同：`127.0.0.1:<adb_local_port>` → `phone_wg_ip:<adb_target_port>`
   ，手机普通 App UID 中转入口使用 15555。

### 命令与工具

- `/phone wg status`：查看配置/helper 进程与健康、监听端口、对端握手与收发字节、
  转发端口与活跃连接、最近错误与重试信息；
- `/phone wg start|stop|restart`：幂等开关/重启 helper（会同步保存 `network.enabled`）；
- `/phone wg config`：client 模式显示「服务器侧需要添加的 Peer 片段」，server 模式显示
  「手机端完整 WireGuard 配置」；
- LLM 工具 `phone_wireguard`：`action=status|start|stop|restart|config`，与命令同一套逻辑；
- `/phone status` 末尾附一行 WireGuard 摘要（运行状态/对端/最近握手）。

### 配置项（`network.wireguard` 参数）

「组网」使用统一的 `network.enabled` 开关与 `network.provider` 选择器。选择 `wireguard` 后显示本组参数：`client` 显示服务器参数，`server` 显示监听与手机接入参数。各服务隐藏的参数保持已保存值。

| 配置项 | 默认 | 适用模式 | 说明 |
| --- | --- | --- | --- |
| `network.enabled` | false | 通用 | 开启且 `network.provider=wireguard` 时运行 helper；关闭恢复 ADB 目标 |
| `mode` | client | 通用 | client=连接已有 WG 服务器；server=本插件当服务器 |
| `server_endpoint` | 空 | client | 要连接的 WG 服务器 `host:port`（必填，仅 IP:port） |
| `server_public_key` | 空 | client | 服务器公钥（base64 32 字节，必填） |
| `listen_port` | 51820 | server | 监听 UDP 端口（client 模式由系统分配） |
| `public_endpoint` | 空 | server | 手机侧可访问地址（必填，可省略端口） |
| `preshared_key` | 空 | 通用 | 可选 PSK（双方保持一致） |
| `interface_address` | 按模式 | 通用 | 本机 WG 地址（CIDR）：client 默认 `10.66.0.2/24`、server 默认 `10.66.0.1/24` |
| `phone_wg_ip` | 按模式 | 通用 | 手机在 WG 网的 IPv4 地址（ADB over WG 目标），须在本机网段内 |
| `adb_local_port` | 15555 | 通用 | helper 在 127.0.0.1 监听的 ADB 隧道端口；0=关闭 ADB over WG |
| `adb_target_port` | 5555 | 通用 | 手机入口；Phone ADB Relay 使用 15555 |
| `socks_port` | 0 | 通用 | 环回 SOCKS5 TCP 代理端口，0 关闭 |
| `auto_adb` | false | 通用 | helper 健康后自动把 ADB 目标切到隧道，停止/异常恢复 |

### 状态与健康判定

helper 每 ≤2 秒原子写一次状态 JSON（`wireguard/phone-wg-status.json`）。插件以「进程存活 +
状态文件 15 秒内更新且报告 running」判定健康；状态文件缺失/过期/进程退出按临时失败处理，
30 秒起指数退避重试，连续 4 次失败收敛为不可用。helper 缺失、配置/密钥非法、helper 退出码
2（配置非法）或 3（建 WG 接口失败）属确定性失败：只记录一次明确原因并停止自动重试；
修改配置保存或 `/phone wg start` 会清除不可用状态重新尝试。

### 无 root Android 接入

1. 手机开启网络 ADB 调试；通过已授权 USB ADB 执行 `adb tcpip 5555`，或使用设备提供的 TCP 调试入口。手机需有可访问的 `127.0.0.1:5555` adbd。
2. 官方 WireGuard App 导入隧道配置并启用。按应用分流时允许 `fun.acat.phonerelay`。
3. 安装随插件分发的 `bin/android/phone-adb-relay.apk`，打开 **Phone ADB Relay**：填写手机 WG 地址与唯一允许的插件 WG 地址，点击启动。
4. 插件配置 `network.wireguard.adb_target_port=15555`、`auto_adb=true`。连接路径为插件环回端口 → WG → 手机 App UID → `127.0.0.1:5555`。
5. 在 `security.background_keep_packages` 中保留 `com.wireguard.android` 与 `fun.acat.phonerelay`。通知栏或组件界面的停止按钮关闭中转与全部活动连接；隧道接口消失时组件自动停止。

Android VpnService 按 UID 选择路由，Phone ADB Relay 的回包由普通 App UID 进入隧道；组件保留 ADB 自身授权。详细安装和构建见 [组件说明](../helper/android-relay/README.md)。

### 通用 TCP 代理

设置 `network.wireguard.socks_port` 为本地空闲端口，即可使用 `127.0.0.1:<socks_port>` 的 SOCKS5 CONNECT 访问 peer AllowedIPs 内的 IPv4/IPv6 目标，不必逐项创建固定转发。代理接受 IP 地址请求；域名由客户端解析后传入 IP。UDP/IP 层转发使用独立网络网关提供。

### 安全注意

- 私钥只写插件数据目录 `wireguard/keys.json` 与 `wireguard/phone-wg.json`（0600、目录 0700），
  不写日志；不要把 `keys.json` 或 `/phone wg config` 的私钥内容发到公开渠道；
- server 模式 `public_endpoint` 与 `AllowedIPs` 按最小范围配置；公网部署建议配合防火墙
  只放行 UDP `listen_port`，并使用 `preshared_key`；
- SOCKS5 和 ADB 转发监听 `127.0.0.1`；代理目标受 peer AllowedIPs 限定，网段外请求直接拒绝；
- 手机端 WireGuard App 未握手时状态显示「尚未握手」：检查 `public_endpoint`/端口可达性。

### 故障排查

- `/phone wg status` 显示「helper 不存在」：插件只随包分发 Linux x86_64 的 `phone-wg`；其他平台请按
  `helper/phone-wg` 源码自行编译后放到插件根目录 `bin/phone-wg`（Windows 还需自备 WireGuard
  `wintun.dll` 并以管理员运行），重新安装插件包不影响该文件时也可保留；
- 显示「不可用：…配置…」：按提示检查字段（client 需 `server_endpoint`/`server_public_key`，
  server 需 `public_endpoint`/`listen_port`，`phone_wg_ip` 要在 `interface_address` 网段内）；
- 日志中的 `[phone-wg]` 行是 helper 的 stderr（启动/握手/转发错误原因）；
- 手机连不上 server 模式：确认 UDP 端口已暴露、`public_endpoint` 填手机可达地址、防火墙放行；
- ADB over WG 不通：确认隧道握手、手机网络调试入口与 `adb_target_port`。官方 App 手机检查 Phone ADB Relay 状态、允许的插件 WG 地址与应用分流；中转入口为 15555。`auto_adb=false` 时把 ADB 目标手动指向 `127.0.0.1:<adb_local_port>`。

## 图文与视频内容任务

默认精读模式下，`phone_content` 为每篇帖子或视频创建独立任务。图文在打开详情前调用 `begin(kind="post", content_id="帖子ID")`，视频先打开并确认播放起点，再调用 `begin(kind="video", content_id="视频ID")`。`read` 返回本次理解与已理解范围，`status` 查看任务，`finish` 结束；切换内容前结束当前任务。

图文从抓包详情对象按内容 ID 关联完整正文和图片 URL，再使用本次响应中的原图；推荐内容、头像和评论不混入正文。未可靠关联时使用可见页面和截图，明确说明正文可能不完整。抓包素材只在内容任务进行中采集，受单响应和总大小限制。

视频首次默认试看 8 秒；独立调用 `decide(decision="continue", reason="原因")` 后，下一次 `read` 默认续看 20 秒。音频持续缓存，关键帧按配置频率采集，按时间游标顺序读取，模型判断期间的内容也保留。超过单批图片数时分批理解；模型失败不推进游标。`phone_watch_media` 使用同一任务机制；默认精读模式下续看需要兴趣判断，`flexibility.enabled` 与 `flexibility.free_browse` 开启时可直接续看。

`decide` 的选项包括 `continue`、`comment`、`read_comments`、`reply_comment`、`like`、`favorite`、`skip`。理解正文后，可独立决定 `comment` 对原帖发表感想，再申请评论名额；决定 `read_comments` 后通过 UI 工具阅读评论，只有对具体已读评论想回复时才决定 `reply_comment(target="评论原文片段")` 并申请互动名额。决定本身不执行点赞、收藏或发布；看评论不等于回复，点赞收藏均可不做。

原音频片段做峰值归一化后与图片优先联合交给模型，原始 PCM 在任务中保留；模型不据此判断实际响度。只支持文字占位的音频适配器使用已配置 STT 转写；不支持音频且无 STT 时明确返回仅画面说明。模型适配器需真正传输音频，支持 `audio_urls` 参数本身不代表实际音频输入能力。语音转写不包含完整音乐和语气信息。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `media.enabled` | true | 视频内容理解开关 |
| `media.preview_seconds` | 8 | 首次试看时长，3–60 秒 |
| `media.seconds` | 20 | 每次续看片段时长 |
| `media.max_seconds` | 60 | 单个理解片段上限 |
| `media.frame_interval_seconds` | 4.0 | 关键帧采集间隔，1–60 秒 |
| `media.max_frames` | 4 | 单批提交图片数，1–8 张 |
| `media.audio_enabled` | true | 采集声音；关闭后仅看画面 |
| `media.audio_source` | output | 设备播放声音；mic 使用麦克风 |
| `model.vision_provider_id` | 空 | OCR、图片、图文与媒体关键帧共用模型；留空使用图片描述模型，再使用当前会话模型 |
| `model.asr_provider_id` | 空 | 统一语音转写模型；空时使用当前 STT Provider |
| `media.asr_timeout_seconds` / `media.vision_timeout_seconds` | 60 | 各模型调用超时秒数 |

素材使用 `perception.screenshot_auto_clean` 和 `screenshot_retention_minutes`。正常执行中的任务保护全部素材；任务结束后清理已过期文件，其余到期清理。自动清理关闭时正常结束素材保留。失败、取消、停止或运行者失效立即回收任务素材，文字摘要与经验保留。`media.keep_audio` 为兼容读取字段，内容任务的音频由统一素材策略管理。

`/phone watch [秒数]` 同样使用内容任务理解当前视频，非 Agent 命令在返回后完成任务；Agent 工具可继续按兴趣续看。小米 Token Plan 的原音频通过同源 OpenAI 兼容接口传输，保持原有模型与认证配置。阿里云 OpenAI 兼容接口使用 data URI 传递原音频并请求文字输出，音频理解需选择具备音频输入能力的模型。

### 观看进度与轮询

Agent 调用 `phone_watch_media` 时，每次最多等待约 20 秒。返回 `status=processing`
表示同一段仍在采集或分析；保持页面并再次调用领取原结果，不重复开始、重新播放或切换
内容。取得 `summary` 与 `understood_until` 后才表示这一段已理解。`action=finish`
取消在途处理并停止采集，Agent 结束也会清理。

### 分段视频识别

「任务与媒体模型」的 `model.video_provider_id` 选择支持 `video_url` 的 OpenAI 兼容 Provider（如 Qwen Omni）。宿主须安装 FFmpeg。流媒体按 2 FPS、最长边 480 像素采集屏幕，按内容游标逐段编码为 MP4；单段最多 60 秒、文件最多 6 MiB，Base64 最多 8 MiB。模型分析期间继续采集，续看包含分析期间的画面，采集累计最多 15 分钟或 128 MiB。临时 MP4 在本段请求结束后删除，源采样按内容任务生命周期管理。

选择视频模型时，直接将带设备原音轨的分段 MP4 交给同一模型，同时理解画面与声音；独立语音模型用于音频模式、未选视频模型的关键帧链路，或开启「视频音轨单独识别」时的音轨转写。无原音频的 MP4 包含生成的静音占位轨，并在模型提示中明确标注。`mode=frames` 始终只传画面，`mode=audio` 使用语音链路。留空视频模型时按音频与关键帧识别。各供应商视频协议和容量要求以模型接口为准，模型不可用会返回错误。

`phone_watch_media` 默认 `action=watch` 顺序观看下一段；`action=finish` 结束本会话观看并停止采集，不录制新片段。Agent 执行结束也会自动收尾。

### 视频音轨单独识别

`model.video_audio_separate`（「视频音轨单独识别」）默认关闭，视频模型接收带设备原音轨的 MP4。选择的视频模型只能理解画面时，可自行开启：插件将同一时间段的音轨交给 `model.asr_provider_id`，视频模型接收保留原音轨的 MP4 与转写文字，声音识别以转写为准。未指定语音模型时会提示配置；`mode=frames` 不采原音频、不转写。此开关按下一段观看实时读取。

### 连续观看的前情

每次续看会向识别模型附带同一内容任务的已理解摘要和时间范围，保留首段定位与最近三段，总长最多 3500 字符。该上下文仅用于衔接人物、事件与未完话题；模型按本段新增画面和声音作答，不能把前情当成本段再次发生的事实。前情以文字传入，视频文件仍按当前游标范围分段，不重复传输前段素材。同一 App 切到另一条视频时先结束观看；新任务不继承前情。

### 完整视频观看与大小阈值

`media.full_video_enabled` 默认关闭。开启后，工具需明确 `stream_kind=video`（点播）或 `live`（直播）；直播始终分段。点播优先使用 `video_url` 获取手机最近五分钟视频流量中已观测的完整文件，HTTP 部分响应与分片清单不作为完整文件。

`media.full_video_max_mb` 为完整观看大小阈值（默认 6 MiB，可设 0.25–6 MiB）；响应头和下载实际字节数超过阈值时转分段，不向模型上传超限文件。`media.full_video_max_seconds` 默认 300 秒，范围 3–600，超过时长上限也转分段；所选模型仍需支持对应时长。

原文件不可获取时，先在手机暂停到视频起点，通过 `phone_screen` 确认总时长与播放按钮坐标，再调用观看工具并传 `duration_seconds`、`play_x`、`play_y`。工具先准备音画采集，再点击播放；从头录制最多 300 秒，并受完整观看时长上限约束。长录制每次最多等待 20 秒，返回 `recording_full` 时继续调用观看工具，保持页面播放；整条录完后一次交模型识别。录制文件超过大小阈值时，从已采集缓存按游标切片，返回 `content_complete` 表示缓存已完整看完。原始音轨按时间窗流式导出，避免把长 PCM 一次读入内存。

完整模式中的视频类型、起点和总时长须由当前页面确认；没有确认的点播时长时不会把一次短采集标为完整。关闭完整模式时，手动 `/phone watch` 可进行即时片段识别；完整流程由 AI 工具确认参数后执行。

## App 操作经验自动写入

打开 `prompt.app_memory_enabled` 后，成功的导航操作和后续页面观察组成经验候选；任务结束时模型只提炼可复用的 App 布局、入口和步骤。失败操作、密码、验证码、个人消息与帖子正文不作为经验。经验只写插件本地档案，相同 App/页面更新为更高版本。

写入失败进入持久化待写队列，指数退避、最多 5 次，目标位置保持不变；错误与待写数量在 `phone_status` 查看。手动 `phone_app_remember` 仍可记录经验。经验索引独立构建（`semantic_app/`），向量模型由 `model.app_memory_embedding_provider_id` 选择，留空继承聊天记忆向量模型。

## 主动分享策略（看/分享两重判断 / 目标由聊天记忆决定 / 白天免打扰）

自刷、随机、持续刷玩手机时，先由 AI 自己的兴趣决定「看不看、看多久」；中途不感兴趣
可以直接退出，看完/玩完后再单独判断「分不分享、要不要互动」；分享目标由 AI 根据最近
聊天记忆判断：

- `phone_recent_chat` 返回**可主动分享的会话列表**：群聊（含最近聊天摘要）+ 最近有交流的
  私聊用户（`auto.share_user_recent_hours`，默认 24 小时内聊过），并显示当前分享时段状态；
  自刷任务未先调用它时，分享工具会拒绝（`phone_chat_memory_checked` 打标校验）；
- AI 从列表里选合适的群/人传给 `phone_share_to_user(target=...)`，同一内容只发一次、
  短时间别刷屏（建议每轮≤3 条）；私聊目标若不是最近有交流则被拒绝，没有固定目标兜底；
- **分享内容必须是链接或截图，禁止纯文字**：链接优先——模型显式传入，或由工具自动从最近
  抓包 flow（`share_url/jump_url/link` 等）提取；App 分享按钮会触发分享接口，通常能抓到
  链接；点击「复制链接」后可调用 `phone_clipboard` 读取本次剪贴板，再将核对过的链接传入
  分享工具。剪贴板读取复用 scrcpy 控制协议，设备控制和截图均选择 ADB 时也可按需启动控制通道；
- **帖子截图**：`content_type=post`（默认）在同一页面向顶部滚动，两次边界稳定后重新截图，
  忽略中途保存的 `screenshot_path`。页面切换、内容不可观察或超过时间/滑动次数时返回错误；
  `content_type=video` 保留当前视频画面，`screen` 用于已确认的当前画面，两者可复用已有截图；
- **同一目标会话分享冷却**：自刷/随机/持续刷任务成功分享后记录目标时间戳，冷却时长由
  `auto.share_cooldown_minutes` 配置（默认 30 分钟，0=不限）；冷却内向同一群/人再次分享
  会被工具拒绝并提示剩余时间，避免一直给对应会话发内容刷屏；用户直接任务不受冷却限制；
- 默认分享时段 `08:00–22:00`（`auto.share_timezone=Asia/Shanghai`，中国时区）：时段外为
  免打扰，自刷/随机/持续刷不主动分享；用户直接任务仍可正常分享；
- 配置：`auto.share_quiet_hours_enabled`、`auto.share_start_hour`、`auto.share_end_hour`、
  `auto.share_timezone`、`auto.share_user_recent_hours`、`auto.share_cooldown_minutes`；
  分享目标由 `phone_recent_chat` 的最近聊天与群/人的兴趣决定。

## 用户任务优先调度

AI 自刷/随机/后台玩手机期间，用户在会话里提出手机相关任务（消息命中手机关键词、或用户
会话里调用了手机工具）时：

1. 插件登记用户任务为高优先级，**中止正在跑的自主任务**（持续刷轮次会被删除，其他
   自主任务请求停止），自刷/随机循环在用户任务期间不再创建新轮次；
2. 自主任务后续的工具调用会收到「用户任务优先，请收尾让路」提示，立即停下；
3. 用户任务结束（`on_agent_done`）后，若已无其他用户任务，**自动恢复持续刷**并把下一轮
   排程时间置 0（立即开始），无需用户手动操作。

配置项 `auto.user_priority`（默认开）控制该调度开关。

## Skill 驱动行为

详细行为规则放在插件内置 Markdown 手册（`skills/<name>/SKILL.md`）里，代码只提供工具，
模型在任务开始前通过 `phone_skill` 工具按需读取：

- `skills/phone-autonomy/SKILL.md`：人格化自主浏览手册（先观察再行动、按人格决定看什么/
  停留多久/是否点开详情或评论、先查收件箱、理解内容并用 `phone_learn` 记录、何时用
  `phone_browse` 快速采样、结束时按人格汇报并写记忆）；
- `skills/phone-media/SKILL.md`：流媒体内容识别手册（视频/直播/音乐只看标题不算看懂，
  值得理解的内容用一次 `phone_watch_media` 录声音转写 + 关键帧描述；无音频时如实说明
  只用画面；同一段不反复识别，不代替正常浏览/互动）；
- `skills/phone-interactions/SKILL.md`：互动行为手册，分「主动评论」「被动回复」「发帖」
  三节（先 gate 申请、自己用低层工具观察与完成、记录结果；被动回复先查收件箱再按心情与
  内容判断；失败就停、绝不重复点发送；常见入口只作参考，不写死流程）。
- `skills/phone-verification/SKILL.md`：人机验证/做题手册（识别滑块/顺序点击/识图/拼图/
  答题页，两阶段 `phone_solve_verification` 流程，`phone_bypass_verify` 手动兜底，失败就停
  并汇报）。
- `skills/phone-housekeeping/SKILL.md`：手机整理手册（何时清理后台、`phone_clean_background`
  两种模式、注意事项与清理后复核）。

手册是**被动参考文档**（不是系统指令）：`phone_skill` 返回时会附带防注入说明，并限制单份
手册最多 8KB。AstrBot 自带的 plugin skill 目录扫描在 non-computer-use 运行时模型读不到文件，
因此由本插件的 `phone_skill` 工具自行读取。

```
/phone wg [status|start|stop|restart|config]  查看/开关 WireGuard 组网；config 显示导入用配置
/phone verify [status|resume <id>|cancel <id>]  查看/恢复/取消验证等待（人工协助）
/phone watch [秒数]                     直接识别当前正在播放的内容（默认 20 秒，便于人工验证）
/phone novelty [status|reset]           查看内容新鲜感/厌倦感状态，或清空全部状态
/phone stop [job_id|all]                停止本插件任务并回桌面清理后台
```

`/phone open` / `/phone browse` 支持通过类型识别的已安装 App 的中文名、别名或包名（由 AI 先用
`phone_list_apps` 发现或回桌面看图标）；`/phone browse` 缺省参数来自配置（默认抖音、5 条）；`/phone auto on` 的 cron 缺省取
配置 `auto.cron`，例如 `/phone auto on douyin,bilibili 0 */2 * * *` 表示每 2 小时
浏览一次抖音与 B 站。

`/phone continuous on` 可带两个可选参数：间隔秒数（10–3600）与每轮 token 预算；
`/phone stop` 留空停止本插件创建的全部定时/后台任务（含正在跑的一轮）并停实时屏幕、
scrcpy、回桌面清理后台，也可只停指定 `job_id` 或 `all`。

`/phone quota` 额外支持 `audit [小时]`：对照 AstrBot `provider_stats` 统计同会话窗口内
模型实际用量与插件记账（不传小时时取 `quota.window_hours`，默认 24 小时；显式范围 1–168 小时），便于核对 token 差异来源。

## 常见问题

**为什么 `/phone quota` 的用量和 AstrBot 面板总用量不同？**
两者口径不同：`/phone quota` 只统计手机相关 run（手机工具/play/任务会话），AstrBot 面板
是全部请求（含普通聊天）的总用量；普通聊天不会计入手机额度。

**为什么对账有少量估算误差？**
运行中先按输入文本与工具步估算，Agent run 结束后才从 `provider_stats` 读该 run 累计实际
usage 补记差额；查询或异步写入未就绪、第三方 runner/DB 异常时会保留估算并记 warning。
所以同一时刻看到的可能是估算值，run 结束后才对平；`/phone quota audit` 可对照实际数据。

**为什么 `/phone quota audit` 的实际用量与插件记账仍有差异？**
audit 按同会话窗口对照模型实际总量与插件条目：插件只对账手机相关 run，窗口内同一会话
的普通聊天请求也会出现在 `provider_stats` 里，属于口径差异；既有记录不回溯补记。

**切换 `model.provider_id` 后自主任务仍用默认模型？**
检查三点：① 当前任务是否为用户对话/普通手动命令会话（该配置只作用于自主任务）；② 配置
是否已在 AstrBot 原生插件配置页保存并由框架重载（后续自主任务请求使用新模型）；③ 所选
Provider 是否存在且支持图片输入与工具调用——不存在时插件会记 warning 并回退默认模型，
可在 AstrBot 日志确认。

**手机截图/工具调用失败，模型说看不到图片？**
检查 `model.provider_id` 选中的模型是否支持图片输入与 function calling；不支持时改选
多模态 + 工具调用模型，或留空使用默认会话模型。

## 安装

1. 把本目录放到 AstrBot 的 `data/plugins/astrbot_phone_control_mirror/`（目录名需与
   `metadata.yaml` 的 `name` 一致）。
2. ADB 可填写手动路径或通过 PATH 提供。启用手机连接并重载时，缺失的 ADB 按系统与架构从 Google 官方下载到插件数据目录；官方未提供匹配平台包时提示手动提供。
3. ADB 地址/端口默认留空（未配置时插件假开启，面板与配置可用）；在「ADB 连接」中填写实际地址（
   如 `192.168.250.x:5555`），并确认容器可访问该端口；如需中文输入，安装并启用
   ADBKeyboard（`com.android.adbkeyboard/.AdbIME`）。
4. 保存配置后框架重载插件；手机操作连接实际设备，连接失败会返回具体原因，配置入口保持可用。
5. 私聊机器人发送 `/phone status` 验证连接；再用 `/phone browse douyin 3` 验证浏览。

默认感知来源为 `adb`、scrcpy 走仅控制通道，插件运行只依赖 Python 标准库与 AstrBot
自带依赖（`mcp` / `pydantic`）；启用 scrcpy 视频镜像（`perception.screen_source=scrcpy`，或 `auto` 且
`perception.live_screen_enabled=true`
或 `scrcpy`）时使用运行环境安装的 PyAV（`av`，wheel 自带 ffmpeg 库）实时解码，
无 PyAV 时回退宿主机 `ffmpeg` 管道；`requirements.txt` 不声明 mitmproxy（抓包为可选独立 venv 依赖，见「手机流量抓包识别」）。

## 权限与安全

- 默认 `security.require_admin = true`：只有 AstrBot 管理员（`role == "admin"`）、
  `security.allowed_user_ids` 白名单用户、以及插件自己的定时主动任务可以操作手机。
- 被拒绝的工具调用返回带用户 ID 的 `error:` 提示，便于用户把自己加入白名单。
- `security.allow_interactions` 授权 `like` 点赞与 `favorite` 收藏；两者共用
  `security.max_likes_per_session` 的单轮上限（默认 5，0=禁止），一次 Agent 任务结束后重新计额。
  先 `phone_interaction_gate(kind="like"/"favorite")` 预约，观察按钮后操作一次，再用
  `phone_interaction_record` 记录成功或失败；待完成预约也占额，失败释放。已有激活状态时跳过。
- 评论、被动回复、发帖由 `allow_comments` / `allow_passive_replies` / `allow_posts` 分别授权。
  互动工具负责流程授权和额度记账，低层点击、输入及 shell 的语义由模型遵守互动流程。
- `security.allow_shell_tool` 默认关闭。开启后可调用 `phone_shell(command, timeout_seconds=0)`，
  在 Android 设备当前 ADB 身份下执行前台命令；默认超时与上限均为 `adb.command_timeout`，
  命令执行一次，返回 `exit_code`、`stdout`、`stderr`，每路最多 8 KiB，超长输出带截断提示。
  工具复用设备权限、占用、暂停、取消与期限；不要启动脱离会话的后台任务。
  非零退出码、连接失败和超时均如实返回；结果不确定时先检查设备状态。
- 截图与 browse 证据落在插件数据目录，不写入插件代码目录。

## 运行要求

- AstrBot `>= 4.27.1, < 5`（已在 4.29.1 验证）。
- **宿主平台**：ADB 官方自动准备范围为 Linux x86_64、Windows x86/x86_64、macOS x86_64/arm64；其他架构手动提供 `adb.path`。WireGuard helper 随包提供 Linux x86_64，其余平台按 `helper/phone-wg` 构建后放入插件根目录 `bin/phone-wg`；Windows 还需提供 WireGuard `wintun.dll`。
- **Windows 降级**：自备 adb 后核心 ADB 控制可用；依赖 Linux 进程监护或 `sh`/ffmpeg 管道的实时屏幕
  视频解码、抓包与未编译的 WireGuard helper 会降级或不可用，状态与日志会给出原因（不支持的平台不会
  影响插件加载与面板）。
- 容器/宿主机可访问模拟器 ADB 端口；adb server 由插件首次连接时自动启动。
- 流媒体内容识别（可选）：转写声音需要 AstrBot 已配置语音识别（STT）Provider，画面
  描述沿用 AstrBot 图片描述/OCR Provider；两者不可用时工具会如实降级并在结果中说明。
- WireGuard 组网（可选）：Linux x86_64 使用随包 userspace helper（`bin/linux-x86_64/phone-wg`）；
  其他平台可自行编译后放到 `bin/phone-wg`。Linux 容器无需 `NET_ADMIN`/`/dev/net/tun`、无需安装
  `ip`/`wg`；Windows 需管理员权限并提供 WireGuard 官方 `wintun.dll`。server 模式需要把 UDP
  `listen_port` 暴露到手机可达网络。密钥与 helper 配置位于数据目录 `wireguard/`（0600）。
- 数据目录：`data/plugin_data/astrbot_phone_control_mirror/`（`adbhome/`、`diary/`、
  `screenshots/`、`media/`、`learning.jsonl`、`novelty.json`、`wireguard/`）。

## 输入、静默交付与图片保存

文字点击先选择屏幕内启用的精确同名控件，避免页面标题等包含相同文字的容器抢先命中。
部分屏外控件点击可见区域中心；完全屏外目标先滚动到可见位置，直接坐标须在屏幕范围内。
`phone_screen` 保留空白输入框的坐标和焦点信息，即使节点没有文字与 clickable 标记也可定位。

`phone_status` 返回设备类型和软键盘状态。模拟器可直接注入文字，以编辑框聚焦和实际关键词确认输入；UI 中可用的 hint 会标为 placeholder，信息不足时明确提示。`phone_input_text(replace=true)` 先清空实际输入；`press_enter=true` 只在核对关键词后回车，否则先观察再提交。输入后核对实际值，未确认时重新聚焦当前编辑框并按原语义重试一次。独立搜索按钮和回车提交方式按当前 App 页面选择。

操作期间过程文字在工具轮结束前缓冲，手机工具轮保持静默，整次任务完成后发送一次最终结果。可使用手机工具的授权会话会先缓冲单轮文本，以判断该轮是否操作手机；普通聊天保留完整正文。`phone_share_to_user` 正文需先总结到 100 字以内；已分享到当前会话的内容在收尾时保持静默。

图片保存配置位于独立的 `image` 卡片：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `image.auto_save_images` | false | 保存图片开关 |
| `image.save_images_both` | false | 同时保存服务端与手机；开启时隐藏主要位置选择 |
| `image.image_storage_location` | server | 关闭两地都存时选择 server（AstrBot 服务端）或 phone（手机） |

AI 在图文 `read` 后调用 `phone_save_image(image_index=0, description="实际图片内容", reason="喜欢的理由", kind="sticker", tags=["开心"])`。编号从 0 开始，与输入原图顺序一致。仅当前已理解图文中的关联原图可保存，支持 PNG/JPEG/GIF/WebP，单图最多 20 MiB。

服务端原图保存在插件数据目录 `saved_images/files/`，`saved_images/index.json` 保存图片编号、内容描述、标签、图片/表情类型、来源 App/内容/会话、哈希、大小/格式、时间与两端路径；内容任务结束和临时素材清理不会删除图片库。手机原图保存在 `Pictures/AstrBot`，规范存储路径、手机 SHA256 和 MediaStore 索引均核验。相同图片去重，两地保存一端失败时保留已保存一端及可查询错误，并明确返回未完成。

后续通过 `phone_saved_images(query="开心表情")` 查询描述和路径，`phone_saved_images(action="to_phone", image_id="查询返回的完整编号")` 可将服务端原图传到手机。查询在保存开关关闭时仍可用；传手机需开启保存。引用时按图片记录和实际路径选图，保存与分享独立决定。


视频 `read` 返回 `understood_until` 与 `captured_until`；模型分析期间继续采帧/录音，续看从上一段末尾消费已缓存素材。`status` 展示帧数和分析状态，结束或停止时回收采集及在途分析。

后台保留名单默认包含 `com.wireguard.android`、`com.tailscale.ipn` 和 `fun.acat.phonerelay`。
保存的标准 WireGuard + Tailscale 双项默认名单会自动升级为当前默认值并保存；自定义名单与显式空名单保持配置值。

命令输出：`command.status_as_image`、`command.help_as_image` 默认开启，分别控制 `/phone status` 与 `/phone help` 的图片输出。关闭对应开关后发送文字；图片使用 AstrBot HTML 渲染服务与插件纯文字卡片模板，渲染失败时提示并附上文字。

Dashboard「记忆索引」可切换 App 操控经验与聊天学习/浏览索引，查看模型、维度、更新时间、正文及实际向量；支持来源筛选、关键词搜索与分页。查看不会调用向量模型或启动设备。

LivingMemory 同步按其当前访问规则、身份别名和记忆作用域写入：user 作用域随同一用户跨会话共享，session 及隔离会话按来源会话保存，global 按全局规则保存。用户发起的后台任务以发起人解析身份；规则接口未就绪或来源未获授权时会返回同步失败原因。

Dashboard「浏览与学习」通过内容顶部标签切换浏览日志和学习记录。删除原始记录后关联检索索引立即失效；日志截图文件保留，已同步到其他记忆插件的副本由对应插件管理。

「记忆索引」可删除单条向量索引，原始经验、学习记录与浏览日志保留。删除后该条向量不再参与语义检索，后台重建保持删除结果。原始档案的直接查询与管理独立进行。

「记忆索引」的「相似关系图谱」按同一索引的向量余弦相似度连线，支持阈值/节点上限、搜索/来源筛选、缩放、拖动与节点详情；节点可删除索引。连线表示语义相近，不表示事实或因果；图谱查看不调用向量模型。


### 发帖与回复配图

开启图片保存后，`phone_saved_images` 支持按描述/标签查询服务器和手机本地保存图片（storage=server/phone/all）。Agent 按上下文决定是否配图；取得互动预约后用 prepare 提交图片编号、互动类型与语义理由，校验原图并准备到相册，再在 App 选图检查预览。无相关图片时使用文字；准备图片不发布、不计作互动成功。


### 应用类型与启动限制

已安装第三方应用由模型根据包名、名称及安装版本识别类型。银行、支付钱包、证券、基金、保险、贷款、理财、加密资产交易等金融类应用拒绝打开；类型未知、置信度不足或识别失败时同样拒绝。普通工具、命令与信息流浏览共用启动校验，安装版本或设备变化后重新识别。识别使用「自主任务模型」指定 Provider，留空使用当前会话模型；分类只发送应用元数据，并计入模型用量。`phone_list_apps` 展示识别类型与是否允许打开。


### Tailscale 用户态接入

在「组网」开启 `network.enabled` 并选择 tailscale，填写独立设备名和 Auth Key，或留空密钥后在 Dashboard「组网接入」启动并打开授权链接。CLI/daemon 在启用并重载时从官方稳定源按 Linux 架构下载并校验，保存到插件数据目录；手动路径优先。节点身份保存在插件私有数据目录，运行不修改宿主 DNS 与路由。

手机安装官方 Tailscale 并加入同一网络，将其 100.64.0.0/10 地址填入手机组网 IP；开启组网 ADB 后插件在回环转发并自动切换 ADB，关闭恢复原目标。Android 无 root 可使用 Phone ADB Relay 将 VPN App UID 的 15555 端口中转到本机 adbd；系统级 VPN 对端可填写实际 adbd 端口。Android 同时启用一种 VPN，插件按选择仅运行一种组网服务。

`/phone network status|start|login|stop`（`mesh` 为同义命令） 可查询或控制。停止会关闭配置中的组网开关，身份文件保留，重新开启可复用登录。组网成员与访问端口由控制台授权/ACL 限制。


### ZeroTier 用户态接入

组网服务选择 zerotier，填写控制台私有网络的 16 位 Network ID。点击 Dashboard 启动，复制显示的 10 位节点 ID，在 ZeroTier 控制台成员列表授权后刷新状态；手机官方客户端加入同一网络并授权。节点身份与 Tailscale 分开保存，切换服务会关闭前一节点和转发。

ZeroTier SDK 仅手动提供，在 `network.zerotier.zerotier_library` 填写兼容动态库的绝对路径，架构、SDK API 和运行库需匹配，构建说明见 [组网组件](../helper/mesh/README.md)。SDK 工作进程提供用户态网络，不需要 TUN 或 NET_ADMIN。组网抓包入口仅接受配置的手机 IPv4，ADB SOCKS 仅连接配置的手机地址与端口。


### 经组网地址抓包

先在组网接入页完成节点授权并填写手机组网 IPv4，再将「流量抓包」的传输通道设为 mesh。手机全局 HTTP 代理使用服务端组网 IPv4 与配置的抓包端口，流量经选定网络到达本地回环 mitmproxy；组网断开会撤回代理。

CA 信任方式为 system 时需要 adb root，插件安装系统 CA。无 root 可选 manual，并在组网页下载公开 CA，由手机或 App 配置信任。HTTP 可直接捕获，HTTPS 只有在 App 信任 CA 时能解密，证书固定应用可能拒绝连接。节点私钥不随 CA 下载提供。

停止抓包恢复先前代理；使用者随后修改的代理保持当前设置。只撤回对应反向映射和本次组网代理端口。Tailscale 访问范围由 ACL 管理，ZeroTier 代理仅接受配置的手机 IPv4。

## 工具异常自主汇报

「工具异常汇报」默认启用，手机工具返回错误时由插件汇报主人，适用于用户调用与静默自主任务。首次错误及时发送；后续错误按目标合并，默认每 300 秒最多一条，包含工具名、错误摘要与次数，不依赖 Agent 主动分享。取消、正常工具结果与目标会话分享冷却不会触发；App 经验维护提示仅供内部更新，通知摘要只保留实际操作故障。

- `report.enabled`：开关；`report.cooldown_seconds`：合并发送间隔，单位秒。
- `report.target`：可指定主人通知会话 UMO；留空时，为 `security.owner_ids` 中的主人生成私聊目标。自主任务使用最近实际交互的平台，不向原群聊自动投递。
- 发送失败重试三次；失败次数可在 Dashboard 概览接口的 `error_reports` 中查看，原因记入 AstrBot 日志。未配置主人或实际平台时日志提示补充配置。

媒体分析返回 HTTP 500 时，按实际链路检查 `model.video_provider_id` 或 `model.vision_provider_id`、语音模型，以及模型实际输入模态。Provider 的音频勾选需要与模型官方能力一致，视频输入能力不表示支持原始音频。分析失败会清理进行中的内容任务；修正模型配置后重新 `begin` 再读取，不能从失败任务继续读。

## 自主规则弹性

`flexibility.enabled` 默认关闭，在「自主规则弹性」中切换。开启后显示三类每日次数与独立能力开关，保存后生效。

每日次数使用本组的 `max_comments_per_day`、`max_passive_replies_per_day` 和 `max_posts_per_day`：`-1` 不限、`0` 禁止、正数限额，仍需权限组授权对应互动类型。

`ignore_interaction_cooldown` 解除评论、被动回复和发帖冷却；`free_browse` 允许自由浏览与按需学习；`relax_interest_novelty` 允许低兴趣、低新鲜感探索；`extend_task_budget` 允许单任务预算延展 20%。每项独立生效，总开关关闭后恢复权限组次数与冷却。
开启后，AI 可以偶尔因为心情、好奇心或单纯想看，点开或看完暂时不感兴趣、已经看腻的内容，
可直接打开贴吧、小黑盒、抖音、快手等 App，用屏幕、点按、滑动或 `phone_watch_media` 分段观看。精读流程与学习记录按需使用，重复观看调用直接从游标续看。观看和分享分别决定，独自观看也可以。

配置为正数的单次任务 token 预算提供额外 20% 余量（向上取整），到执行上限时收尾；
预算为 0 时保持不限单次预算。模型调用按实际/估算 usage 继续记账，单次调用可能跨过剩余额度；
后续操作会检查并停止。任务中关闭开关会恢复原预算上限，已用额度保留。
新鲜感曝光和疲劳记录继续累积，阈值作为参考。

滚动总 token 额度、互动开关与限额、分享目标/时段/冷却、金融应用限制、
用户任务优先、取消、暂停与执行期限按当前配置执行。


### 常用配置与条件显示

配置页优先展示 ADB、权限、模型、自主行为和额度。聊天记忆向量模型位于「记忆存储」，只在「保存到插件本地」开启时显示；App 经验向量模型位于模型分组，留空可继承聊天向量模型。

「控制/感知后端」使用下拉选择。选择 scrcpy 展开其参数，auto 使用保存参数或默认值；minitouch 的路径由独立开关展开。流量抓包关闭时仅显示启用开关，保存的参数会保留。

每日评论、被动回复与发帖限额：`-1` 表示不限次数，`0` 表示禁止该类互动，正数表示每日成功与待完成预约合计上限。已有无限次数会自动转换并保留备份；权限开关单独控制授权。


### 自主观看与互动检查

直播在默认精读和自由浏览模式均可选择；用 `phone_watch_media(stream_kind="live")` 从当前时刻分段理解，按运行时规则决定是否续看。直播无需定位点播起点或提供总时长。模型需具备实际的视频或图片/声音理解能力。

自主活动依赖定时浏览、随机玩或持续刷手机至少一种调度开启；评论、被动回复与发帖分别需要权限组授权。运行时会显示各类型当前每日次数和冷却，精读模式评论需要独立判断，发布前申请名额并在完成后记账。技能提供自主评论、发帖的决策入口，具体是否发布仍由人格、内容和实际页面决定。

任务结束或取消时释放本轮未完成的互动预约；记账摘要过长等可修正错误在本轮内保留预约，修正后直接再次记录，不重复发布内容。

### 自主活动的每日时间段

随机玩使用 `auto.random_windows`，持续自动刷使用 `auto.continuous_windows`。在列表中逐项填写 `08:00-10:00`、`19:00-22:00`，每天可以设置多段，也支持 `23:00-02:00` 跨午夜。空列表表示全天。按 `auto.play_timezone`（默认 `Asia/Shanghai`）判定，包含开始、不包含结束；开始和结束不能相同。允许时段外等待，到结束时间中止本类自主任务并释放设备。保存后即时采用新时段，用户直接发起的手机任务独立执行。

### 自主活动模式

在自主行为配置中用 `auto.mode` 下拉选择「随机玩」「自动刷」「定时玩」，对应子项随选择显示。`auto.activity_enabled` 控制是否运行当前模式。随机玩与自动刷分别保存各自时间段，切换后仍保留设置；定时玩使用 cron、App 与汇报会话。保存模式后取消其他自主模式的在途任务，定时排程随模式同步。配置加载保留当前模式及活动开关。`/phone continuous on` 选择自动刷，`/phone auto on` 选择定时玩，`/phone stop` 关闭自主活动。

### 命令图片渲染

`/phone status` 与 `/phone help` 按各自图片开关输出。图片模式通过官方文字转图资源接口生成，并在下载时检查 HTTP 状态、8 MiB 大小上限和完整图片解码。渲染端点失败时框架尝试其他可用端点；渲染服务不可用或响应无效时，消息说明图片渲染失败并附上原始状态或帮助文字。恢复服务后再次查询即可重新生成。


### 媒体模型超时

图文理解、视频识别和语音识别超时会显示对应阶段、Provider 与等待上限。图文与分段视频保留当前任务、已采集素材和已理解游标；先检查模型服务及 `media.vision_timeout_seconds` / `media.asr_timeout_seconds`，再用同一工具重试本段，或 `finish` 结束观看。超时本身不会推进游标或生成理解摘要。设备断开、素材损坏和用户取消按各自生命周期清理任务。


### 验证工具的页面判定

`phone_bypass_verify` 的首次拖动或顺序点击需在当前页面读到验证提示；纯图片挑战可先调用 `phone_solve_verification(mode="auto")`。普通页面按钮使用 `phone_tap` / `phone_swipe`。自动求解的 `captcha`、`quiz` 模式筛选实际检测到的类型，普通页面仅返回摘要并关闭本次验证；未确认通过的真实挑战仍受尝试次数、期限和人工协助约束。


Agent 中 `phone_content(action="read")` 每次等待最多20秒，`processing` 表示同一次采集或分析仍在进行；保持页面并继续 `read` 领取结果。`finish`、停止或插件重载会取消在途分析并按任务规则清理素材。


验证码求解的两次截图分别识别与复核挑战。第二阶段必须返回布尔 `challenge_confirmed=true` 才能执行，普通页或未明确确认时不执行坐标。首次分类与操作计划均属于只读准备，准备完成后才建立验证会话并开始单次动作尝试计时；模型准备失败时可检查模型服务，普通手机操作保持可用。

App文件传输使用手机共享存储或`/data/local/tmp/`普通文件，单文件128 MiB。上传和下载均校验SHA256，传输中断保留目标文件并清理自有临时文件；控制连接结束时数据子连接同步关闭。

### 手机端录制与文件传输

App模式下可调用`phone_record_media(action=start, mode=both, seconds=60)`开始手机内H264/AAC封装；`mode=audio`保存M4A，`mode=video`只录画面。`status`查看实际音视频样本与时长，`stop`结束并下载校验成品，`cancel`清理本会话录制。单次1–900秒、最大128 MiB，控制连接结束会停止并清理手机缓存；录制期间改变屏幕尺寸需重新录制。独立录制与媒体理解分别使用音频资源，开始另一种采集前先结束当前任务。

`phone_files(action=upload, phone_path=手机完整文件路径)`上传当前消息中的文件附件，也可指定已有`file_id`；`download`将共享存储文件下载到插件传输目录，`list`列出文件ID，`delete`按ID清理缓存。单文件128 MiB，缓存总额512 MiB；传输校验SHA256，默认只返回文件ID和元信息，显式`send_to_chat=true`发到当前聊天。

手机端App抓包CA可在Relay App连接页导出，再进入系统安全与凭据设置选择CA证书安装；Android11及以上经系统设置安装用户CA。插件选择手动CA后可以启动代理，目标App是否信任用户CA、是否固定证书决定HTTPS能否解密。系统CA模式在权限不足时明确停止启动；Dashboard展示具体原因与当前信任条件，并提供当前方式的CA下载入口。

保持手机视频就绪时，手机通过独立认证连接推送JPEG，插件只在内存保留最新一帧；截图按250毫秒画面年龄和操作代次校验。画面年龄采用请求往返时钟的保守下界计算，网络排队不会把旧帧视为新帧；截图耗时与画面年龄在面板分别显示。关闭保持就绪后按需采集，90秒空闲释放手机视频资源。


### 常见运行错误

| 错误 | 检查与处理 |
| --- | --- |
| `could not get idle state` | Android 节点采集需要界面短暂静默；持续动画、直播或滚动页面可用 `phone_screen(mode="image")` 观察当前画面，再按截图坐标操作。文本点击需要本次成功采集的节点。 |
| 模型 `403 insufficient_quota` / `Free quota exhausted` | 检查当前视频、图文或语音 Provider 的服务商额度和计费开关；插件 token 预算与服务商免费额度分别管理。恢复额度或选择有可用额度的模型后再开始内容任务。 |
| `未找到 mitmdump` | 在插件持久化数据目录准备独立 mitmproxy venv，将 `traffic.mitmdump_path` 指向实际可执行文件；保存后重载抓包配置并检查 `/phone traffic status`。 |
| `工具错误汇报发送失败` | 检查实际消息平台登录状态、通知目标和发送权限。三次发送失败表示通知未送达；错误汇报状态可在 Dashboard 查看。 |
| `status=cancelled`（内容观看已取消或结束） | 进行中的内容任务已被结束或随插件重载取消，先重新观察页面；新的观看调用创建新的内容任务。 |


### 动态页面的屏幕观察

`phone_screen(mode="image")`直接获取画面，适用于视频、直播和持续动画页面。`mode="both"`或`include_screenshot=true`同时请求节点与截图；节点采集失败时仍返回截图，并明确显示节点不可用及原因。此时按真实画面观察，文本和节点定位须以成功采集的当前节点为依据。仅请求UI节点时，采集失败返回错误。


### 后台手机子Agent

在「任务与媒体模型」开启 `model.work_as_subagent`（默认关闭）。主对话通过 `phone_start_background_task` 提交完整手机指令，立即收到任务ID并继续普通对话或其他工作。AstrBot原生调度器创建独立Agent会话执行手机工具，使用 `model.provider_id` 选择的任务模型；手机端仍由设备租约串行保护。

- `action=start, instruction="..."`：提交任务，结果分享默认发往原会话，可用 `share_target` 指定会话。
- `action=list`：列出当前用户在原会话发起的任务。
- `action=status, job_id="..."`：查询状态和结果摘要。
- `action=cancel, job_id="..."`：取消待启动或正在执行的任务，释放该任务资源。

主Agent收到任务ID后可继续主任务，无需持续轮询。后台Agent直接执行手机工作，完成后使用 `phone_share_to_user` 汇报；主对话结束保持后台任务运行。取消、`/phone stop` 或插件停用会结束对应任务。设备故障、验证暂停、模型额度和互动权限仍按实际状态处理。

状态与最近100条结束结果保存在当前插件实例内；重载插件会结束活动子任务并清空这些状态。`ended`表示宿主已结束任务且未收到正常完成结果，应核对实际汇报。开启时同一手机仅接受一个进行中的子任务；关闭后主Agent可直接操作手机，已有独立任务仍可查询和取消。

独立手机Agent在执行前应用自身的手机工具集合，结果通过 `phone_share_to_user` 投递。该工具的 `target` 留空时使用任务登记的汇报会话；提交任务指定 `share_target` 时需填写可识别且允许分享的真实会话UMO。
